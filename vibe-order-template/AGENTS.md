# 作業ルール

このファイルはAgentが毎回読みます。短く保ってください。
Agentが繰り返し間違えたことだけを足していきます。

## 基本

- 変更前に、関連するファイルと既存テストを確認する。
- 変更は必要最小限にする。
- 新しい振る舞いを追加・変更したら、テストを追加または更新する。
- 完了前に `make check` を実行する。その結果でのみ完了を判断する。
- `.env`、認証情報、秘密鍵を作成・変更・出力しない。
- `main` ブランチへ直接コミットしない。

## この題材のルール（PART 6 で追記）

- データ構造は src/vibe_order/models.py の Pydantic モデルとしてのみ定義する。
- 注文の状態は pending -> cooking -> served の順にのみ進む。逆行させない。
- 新しい振る舞いを足したら、正常系1件と異常系1件のテストを必ず書く。

## 実装前に必ず報告すること

- 変更するファイルの一覧
- 実装の手順
