はじめに

AIがコードを書く時代に、何を学ぶのか

AIは、質問に答えるだけでなく、ファイルを読み、コードを書き換え、テストを実行するようになりました。この教材では、その変化を自分の手で確かめます。

01AIは「答える」から「作業する」へ

先ほどの例を、もう一度見てください。AIはコードを書いただけではありません。ファイルを作り、実行し、失敗を読み、修正し、もう一度確かめました。

Agentic AIとは、AIの使い方のひとつです。目標を与えると、AIが手順を考えます。道具を使って実行します。結果を見て、次の行動を決めます。

Coding Agentは、その考え方をソフトウェア開発に使う例です。

違いをバグ修正で比べます。

従来の生成AICoding Agent
指示「このエラーを直す方法を教えて」「テストが1件落ちている。直して」
AIの出力修正案やコード例修正済みのコードとテスト結果
AIが行うこと質問に答えるファイルを探す、読む、修正する、テストする
人の役割コードを反映し、実行する目標を示し、重要な判断と確認を行う

AIが急に万能になったわけではありません。変わったのは、道具を使えるようになったことです。ファイルを読み、コマンドを実行し、その結果を次の行動につなげます。

ここで大事なこと LLMが自分でPCを操作しているわけではありません。LLMは「次に何をするか」を提案するだけです。実際にファイルを操作し、コマンドを実行するのは、ClineなどのAgentホストです。ホストは、許可された範囲でしか動きません。

止める場所は、モデルの中にはありません。権限、承認、テスト。すべて環境の側にあります。

この仕組みは、コーディング以外にも使えます。書類処理、問い合わせ対応、データ整理。どれも同じ形です。

ただし、この教材はコーディングを題材にします。理由は2つあります。変更内容を差分で確認できること。テストで正しさの一部を確かめられることです。

02なぜ今なのか

AIが開発作業を進められるようになりました。文章がうまくなったからではありません。3つの条件が揃ったからです。

条件何ができるようになったか
ツール利用が安定したAIが「どの操作を、どの引数で行うか」を構造化して出せる
長い文脈を扱えるようになった複数のファイルと作業履歴を保ったまま、何段階も作業を続けられる
開発環境とつながったエディタ、ターミナル、テスト、バージョン管理をAIが使える

この3つによって、AIの役割が変わりました。「次の一行を提案する補完機能」から、「限られた範囲で開発を進めるAgent」へ。

Copilot（副操縦士）から Pilot（操縦士）へ。人の仕事は、実装から設計・検証・判断へ移ります。

ここで、冒頭のアプリに戻ります。あれは本当に提出できるでしょうか。

入力検証が足りないかもしれません。データが再起動で消えるかもしれません。テストに書かれていない要件を壊しているかもしれません。

速く作れることと、正しく作れたことは別です。だから、人がどこで判断するかが問題になります。どんな制約を置くかも問題になります。

03この教材で目指すこと

この教材が扱うのは、AIに開発を任せる方法ではありません。任せながら、品質と責任を保つ方法です。

終わったとき、次のことができる状態を目指します。

  • Coding Agentが何を読み、何を変更し、何を根拠に完了と判断したかを確認できる
  • AIに実装を任せ、その結果をテスト、差分、仕様から検証できる
  • テスト、Linter、CI、権限設定で、AIに任せる範囲を安全に狭められる
  • PythonとLangGraphで、承認と再試行を持つ小さなAgentを設計できる
前提と環境 Python 3.12を使います。プログラミングの基礎とターミナル操作の経験があれば進められます。特定のフレームワークの事前知識は要りません。

モデルは、手元のマシンか授業用のローカルサーバで動かします。クラウドAPIへの課金は前提にしません。設定は付録Aにあります。

04道すじ

この教材では、理解、実験、検証、構築、運用の順に進めます。最初から正しい開発方法を覚えるのではありません。まずAIに任せてみて、その速さと限界を体験します。その後で、任せた作業を検証し、安全にする方法を学びます。
