7.1素のPythonで最小のAgentを作る

PART 3では、ツール呼び出しの4手順を学びました。ホストがツールを示します。モデルがツールを選びます。ホストが実行します。ホストが結果をモデルへ返します。7.1では、この処理をPythonで書きます。

7.1.1ツールに制約を付ける

自分で作るツールにも制約が必要です。プロジェクト外のファイルを読めないようにします。テストの実行時間も制限します。

"""Tools the agent may use. Every tool is a plain Python function with limits built in.

PROJECT_ROOT is the vibe-chat folder (the parent of this agent/ folder), whatever the
current working directory is.
"""

import difflib
import subprocess
import sys
from pathlib import Path

PROJECT_ROOT = Path(__file__).resolve().parent.parent

# Files the agent may overwrite: .py files directly under the project root, or under tests/.
WRITE_ROOTS = [PROJECT_ROOT, PROJECT_ROOT / "tests"]

# Files whose "before" state we keep, so we can show a diff without git.
WATCHED_FILES = ["app.py", "tests/test_app.py"]


def _safe_path(path: str) -> Path:
    """Resolve a path and refuse anything outside the project."""
    target = (PROJECT_ROOT / path).resolve()
    if PROJECT_ROOT not in target.parents and target != PROJECT_ROOT:
        raise ValueError("Files outside the project cannot be accessed.")
    return target


def read_file(path: str) -> str:
    """Read a file inside the project (first 4000 characters)."""
    return _safe_path(path).read_text(encoding="utf-8")[:4000]


def write_file(path: str, content: str) -> str:
    """Overwrite a .py file directly under the project root or under tests/."""
    target = _safe_path(path)
    if not any(root == target.parent for root in WRITE_ROOTS):
        raise ValueError("Only files directly under the project root or under tests/ may be written.")
    if target.suffix != ".py":
        raise ValueError("Only .py files may be written.")
    target.write_text(content, encoding="utf-8")
    return f"Updated {path}"


def run_tests() -> str:
    """Run pytest in the project and return the tail of its output."""
    r = subprocess.run(
        [sys.executable, "-m", "pytest", "-q"],
        cwd=PROJECT_ROOT,
        capture_output=True,
        text=True,
        timeout=120,
    )
    return (r.stdout + r.stderr)[-4000:]


def tests_pass() -> bool:
    r = subprocess.run([sys.executable, "-m", "pytest", "-q"], cwd=PROJECT_ROOT, capture_output=True, text=True, timeout=120)
    return r.returncode == 0


# ---- diff without git ---------------------------------------------------------

def snapshot() -> dict:
    """Remember the current content of the watched files."""
    out = {}
    for rel in WATCHED_FILES:
        p = PROJECT_ROOT / rel
        out[rel] = p.read_text(encoding="utf-8") if p.exists() else ""
    return out


def make_diff(before: dict) -> str:
    """Unified diff between a snapshot and the files as they are now."""
    chunks = []
    for rel, old in before.items():
        p = PROJECT_ROOT / rel
        new = p.read_text(encoding="utf-8") if p.exists() else ""
        if old == new:
            continue
        chunks.append("".join(difflib.unified_diff(
            old.splitlines(keepends=True), new.splitlines(keepends=True),
            fromfile=f"{rel} (before)", tofile=f"{rel} (after)")))
    return "\n".join(chunks) if chunks else "(no changes)"


TOOLS = {"read_file": read_file, "write_file": write_file, "run_tests": run_tests}

agent/tools.py です。_safe_pathは、プロジェクト外へのアクセスを防ぎます。WRITE_ROOTSは、書き込み先を制限します。この2つがない場合、Agentは不要なファイルを読む、または変更する可能性があります。

これは演習用に危険を縮めた書き換えツールです この例はファイル全体を上書きします。実務では、差分を表示し、人間が承認した後で適用する方法が安全です。この演習では、書き込み先を2つのディレクトリに制限します。

7.1.2ツールの定義とループ

"""7.1 — The smallest possible agent, in plain Python.

Run from the vibe-chat folder:   python agent/agent_plain.py

The loop below is the whole idea of an agent:
  1. we give the model a list of tools (SCHEMA)
  2. the model answers with tool calls (or a final message)
  3. WE run the tool and send the result back
  4. repeat, with a hard limit on the number of steps
"""

import json

import requests

from config import BASE_URL, MODEL, HEADERS, API_KEY
from tools import TOOLS

SCHEMA = [
    {"type": "function", "function": {
        "name": "read_file",
        "description": "Read a file inside the project. Use it to look at app.py and tests/test_app.py.",
        "parameters": {"type": "object",
                       "properties": {"path": {"type": "string"}},
                       "required": ["path"]}}},
    {"type": "function", "function": {
        "name": "write_file",
        "description": "Overwrite a .py file inside the project with new content.",
        "parameters": {"type": "object",
                       "properties": {"path": {"type": "string"},
                                      "content": {"type": "string"}},
                       "required": ["path", "content"]}}},
    {"type": "function", "function": {
        "name": "run_tests",
        "description": "Run pytest and return the result.",
        "parameters": {"type": "object", "properties": {}}}},
]

SYSTEM = (
    "You are a careful coding agent working inside a small Flask project. "
    "Use the tools to read files, edit files and run the tests. "
    "Fix the failing test by fixing the application code, not by changing the test. "
    "When the tests pass, reply with a short summary of what you changed."
)


def chat(messages):
    """One call to the OpenAI-compatible endpoint of the shared server."""
    r = requests.post(
        f"{BASE_URL}/chat/completions",
        headers={**HEADERS, "Authorization": f"Bearer {API_KEY}", "Content-Type": "application/json"},
        json={"model": MODEL, "messages": messages, "tools": SCHEMA, "temperature": 0},
        timeout=300,
    )
    r.raise_for_status()
    return r.json()["choices"][0]["message"]


def agent(goal: str, max_steps: int = 12) -> str:
    messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": goal}]
    for step in range(max_steps):
        msg = chat(messages)
        messages.append(msg)
        calls = msg.get("tool_calls") or []
        if not calls:
            return msg.get("content") or "(no content)"       # no tool call: the model is done
        for call in calls:
            name = call["function"]["name"]
            args = json.loads(call["function"].get("arguments") or "{}")
            shown = {k: (v[:60] + "…" if isinstance(v, str) and len(v) > 60 else v) for k, v in args.items()}
            print(f"[{step}] {name}({shown})")
            try:
                result = TOOLS[name](**args)
            except Exception as e:                              # a failure is also a result
                result = f"ERROR: {e}"
            messages.append({"role": "tool", "tool_call_id": call["id"], "content": str(result)})
    return "Stopped: reached the maximum number of steps."


if __name__ == "__main__":
    print(agent("Run the tests, find out why one of them fails, and fix it."))
動かないときに最初に見るところ 接続先は、Clineと同じ共有サーバです。Clineで動いていれば、config.py の4つを揃えるだけで動きます。

model ... not found → BASE_URL のサーバ番号と MODEL の番号が合っているか
502 → そのサーバのOllamaが落ちている。講師に言う
途中で止まる → max_steps に達した。何をしていたかは [n] ツール名(引数) の行に出ています

7.2LangChainで部品をつなぐ

LangChainは、7.1で書いた処理を部品として提供します。最初に6つの概念を確認します。

7.2.1LangChainの6つの概念

概念役割この章で使う場所
Model I/Oモデルへ入力し、出力を受け取る旅行案内とAgentのモデル呼び出し
ChainPrompt、Model、出力処理を順番につなぐ旅行案内の構造化出力

全部を使う必要はありません 必要な部品だけを使います。最初にModel I/OとChainを試します。その後、Agent、Memory、Retrievalへ進みます。

7.2.2小演習：旅行案内を決まった形で出す

自由な文章から特定の項目を取り出すことは困難です。次のプログラムは、出力を場所、地域、行き方、見どころの4項目に固定します。

python agent/demo_structured.py
"""7.2.2 — LangChain: force the model to answer in a fixed shape.

Run from the vibe-chat folder:   python agent/demo_structured.py
"""

from pydantic import BaseModel, Field
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

from config import BASE_URL, MODEL, HEADERS, API_KEY


class Destination(BaseModel):
    name: str = Field(description="Name of the place")
    city: str = Field(description="City or region")
    access: str = Field(description="How to get there from central Mumbai")
    highlight: str = Field(description="What makes it worth the trip")


prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a travel adviser for Mumbai."),
    ("human", "Suggest one place to visit within about one hour of central Mumbai."),
])

model = ChatOpenAI(base_url=BASE_URL, api_key=API_KEY, model=MODEL, temperature=0,
                   default_headers=HEADERS)
structured_model = model.with_structured_output(Destination, method="function_calling")

# Prompt -> Model -> Destination
chain = prompt | structured_model
result = chain.invoke({})

print("Place:    ", result.name)
print("City:     ", result.city)
print("Access:   ", result.access)
print("Highlight:", result.highlight)

"""7.2.3 — The same agent as 7.1, but LangChain/LangGraph run the loop.

Run from the vibe-chat folder:   python agent/agent_langchain.py
"""

from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langgraph.prebuilt import create_react_agent

from config import BASE_URL, MODEL, HEADERS, API_KEY
import tools as t


# The docstring of each tool is what the model sees. 7.2.4 asks you to change them.
@tool
def read_file(path: str) -> str:
    """Read a file inside the project. Use it to look at app.py and tests/test_app.py."""
    return t.read_file(path)


@tool
def write_file(path: str, content: str) -> str:
    """Overwrite a .py file inside the project with new content."""
    return t.write_file(path, content)


@tool
def run_tests() -> str:
    """Run pytest and return the result."""
    return t.run_tests()


model = ChatOpenAI(base_url=BASE_URL, api_key=API_KEY, model=MODEL, temperature=0,
                   default_headers=HEADERS)

SYSTEM = (
    "You are a careful coding agent working inside a small Flask project. "
    "Fix the failing test by fixing the application code, not by changing the test. "
    "When the tests pass, reply with a short summary of what you changed."
)

agent_executor = create_react_agent(model, [read_file, write_file, run_tests], prompt=SYSTEM)


def run(goal: str) -> str:
    result = agent_executor.invoke({"messages": [("user", goal)]}, {"recursion_limit": 30})
    return result["messages"][-1].content


if __name__ == "__main__":
    print(run("Run the tests, find out why one of them fails, and fix it."))

やること 最初に、現在のdocstringで実行結果を記録します。次に、agent/agent_langchain.py の read_file のdocstringを「データを取得する」へ変更します。同じ依頼を実行し、どのツールが選ばれたかを比較してください。

最後に元の具体的なdocstringへ戻します。曖昧な説明がツール選択へ与えた影響を1文で書きます。

ツールのdocstringは、モデルが読む説明です。モデルは、その説明を使ってツールを選びます。

ライブラリは道具です LangChainを使っても、基本処理は7.1と同じです。処理が分からない場合は、7.1のコードを確認してください。実行前に、使用中のバージョンと公式ドキュメントも確認します。

7.3LangGraphで仕事の流れを設計する

次に、処理の流れを作ります。失敗後の分岐、再試行の上限、人間へ確認する位置を決めます。

7.3.1作る流れ

実線が正常な経路、破線が revise による差し戻し

LLMを呼ぶ場所はimplementだけです。ほかの処理は通常のPythonです。

from typing import TypedDict

from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import StateGraph, START, END
from langgraph.types import interrupt, Command

import tools as t
from agent_langchain import agent_executor

MAX_ATTEMPTS = 3        # 7.3.2: the stop condition. Try changing it.


class State(TypedDict, total=False):
    goal: str
    attempts: int
    before: dict          # snapshot of the watched files, taken in plan
    check_output: str
    passed: bool
    diff: str
    decision: str
    review_feedback: str


def plan(state: State) -> State:
    return {**state, "attempts": 0, "before": t.snapshot()}


def implement(state: State) -> State:
    # The only place the model is called.
    prompt = state["goal"]
    if state.get("check_output"):
        prompt += f"\n\nResult of the last test run:\n{state['check_output']}"
    if state.get("review_feedback"):
        prompt += f"\n\nFeedback from the human reviewer:\n{state['review_feedback']}"
    agent_executor.invoke({"messages": [("user", prompt)]}, {"recursion_limit": 30})
    return {**state, "attempts": state["attempts"] + 1}


def check(state: State) -> State:
    # pytest is a node of its own. The model never gets to "say" the tests passed.
    output = t.run_tests()
    return {**state, "check_output": output, "passed": t.tests_pass()}


def route_after_check(state: State) -> str:
    if state["passed"]:
        return "review"
    if state["attempts"] >= MAX_ATTEMPTS:
        return "give_up"
    return "implement"


def give_up(state: State) -> State:
    print(f"\nGave up after {MAX_ATTEMPTS} attempts. Handing over to a human.\n")
    print(state["check_output"])
    return state
ここではまだ組み立てません ノードと分岐は用意できました。グラフの組み立てとcompile()は7.4で行います。まだreviewがないため、ここでは実行しません。

7.3.2停止条件を設計に埋める

MAX_ATTEMPTSは再試行の上限です。3回失敗した場合、Agentは処理を止め、人間へ結果を返します。

無限の再試行は、コストと安全性の問題を起こします。

自分でAgentを作るなら、停止条件も自分で書きます。

なぜ check が独立したノードなのか pytest をLLMに「実行したことにさせる」のではなく、グラフのノードとして必ず通します。PART 5で完了条件をテストにしたのは、ここで効いてきます。Agentが「完了しました」と言えるのは、check ノードが成功を返したときだけという構造になります。

7.4人間の承認・中断・再開

reviewノードで処理を止め、人間の判断を待ちます。差分は、plan で取った控え（snapshot）と今のファイルを比べて作ります。gitは使いません。

def review(state: State) -> State:
    diff = t.make_diff(state["before"])
    answer = interrupt({
        "diff": diff[:4000],
        "check_output": state["check_output"],
        "question": "Approve these changes?",
        "choices": ["approve", "revise", "stop"],
    })
    return {**state, "diff": diff,
            "decision": answer["decision"],
            "review_feedback": answer.get("feedback", "")}


def route_after_review(state: State) -> str:
    if state["decision"] == "revise":
        return "implement"          # send the feedback back to the agent
    return END                      # approve and stop both end here

7.4.1ここで初めて組み立てる

graph = StateGraph(State)
graph.add_node("plan", plan)
graph.add_node("implement", implement)
graph.add_node("check", check)
graph.add_node("review", review)
graph.add_node("give_up", give_up)
graph.add_edge(START, "plan")
graph.add_edge("plan", "implement")
graph.add_edge("implement", "check")
graph.add_conditional_edges("check", route_after_check)
graph.add_conditional_edges("review", route_after_review)
graph.add_edge("give_up", END)
app = graph.compile(checkpointer=MemorySaver())


def main():
    config = {"configurable": {"thread_id": "task-001"}}
    result = app.invoke({"goal": "Run the tests, find out why one of them fails, and fix it."}, config)

    # While the graph is paused at `review`, show the diff and ask the human.
    while "__interrupt__" in result:
        payload = result["__interrupt__"][0].value
        print("\n" + "=" * 60)
        print("TESTS:\n" + payload["check_output"].strip().splitlines()[-1])
        print("-" * 60)
        print("DIFF:\n" + payload["diff"])
        print("=" * 60)
        decision = ""
        while decision not in ("approve", "revise", "stop"):
            decision = input("approve / revise / stop > ").strip().lower()
        feedback = input("What should be changed? > ") if decision == "revise" else ""
        result = app.invoke(Command(resume={"decision": decision, "feedback": feedback}), config)

    print("\nFinished. Decision:", result.get("decision", "(gave up)"))


if __name__ == "__main__":
    main()

Agentが直してテストが通ると、画面に差分が出て approve / revise / stop > で止まります。ここが7.0.2の4番です。Agentは自分で終わりません。

必ず1回は revise する

差分を読んで、1回目は revise を選び、直してほしい点を英語で1行書きます。例：

Do not change tests/test_app.py. Fix app.py only.
Keep the error message exactly "User name cannot be empty."

Agentは、前回のテスト結果とあなたの指摘を受け取って implement からやり直します。2回目の差分が1回目とどう違うかを、REPORT.txt に書きます（7.6）。納得したら approve。

停止条件を変えてみる

agent/agent_graph.py の MAX_ATTEMPTS = 3 を 1 にして、もう一度壊して動かします。1回で直せなければ give_up に行き、人間に引き継がれます。「Agentが諦める」もあなたが設計した動作です。戻すのを忘れずに。

reviseを選ぶと、処理はimplementへ戻ります。Agentは、前回のテスト結果と人間の指摘を使って再修正します。

承認機能には、差し戻しの経路と指摘を渡す仕組みが必要です。

MemorySaverはメモリ上の保存です thread_id により、同じPythonプロセスの中では途中の状態を指定して再開できます。プログラムを終了すると MemorySaver の状態は消えます。

別の日にも再開したい場合は、SQLiteやPostgreSQLなど永続的なcheckpointerを使います。この章では、演習中に止めて再開するところまでで十分です。
副作用は承認の後ろに置く interrupt() を含むノードは、再開時に先頭から実行されることを前提に書いてください。承認前に外部への書き込みを置くと、再開のたびに同じ処理が繰り返されます。

メール送信、課金、ファイル削除などの副作用は、承認の後に別のノードとして置きます。ノードを小さく分けるのは、見やすさのためだけではありません。

7.4.2どこに承認を置くか

置くべきところ理由
取り消せない操作の前削除、送信、公開、課金。戻せないものは必ず止める
影響範囲が広がるとき変更ファイル数や行数がしきい値を超えたら止める
Agentが行き詰まったときgive_up は失敗ではなく、正しい終わり方のひとつ
外部に出るときネットワーク送信、外部APIの呼び出し

演習0で書いてもらった「人間が残すべき確認」の列を思い出してください。あのとき言葉で書いたものを、いまコードとして置いています。

7.5発展：MCPで現在の状況につなぐ

ここまでは、ツールを自分で作りました。MCPは、既存の外部ツールをAgentへ接続するための共通規格です。

この節では、読み取り専用のMCPツールを1つ作ります。外部データの変化によって、Agentの判断が変わることを確認します。

ここでClineに戻る理由 自作AgentからMCPへ接続するには、追加の接続コードが必要です。この節では、MCPクライアントとしてClineを使います。目的は、別プロセスのツールを共通形式で接続することです。自作Agentからの接続は付録Cで扱います。
7.1で書いたツール7.5のMCPツール
Agentと同じPythonプロセスにある関数別プロセスのサーバが提供する関数
自分でSchemaを書くサーバからツール定義を受け取る
自分のリポジトリに密結合同じサーバをClineなど別クライアントも使える
最初に繋ぐものの選び方 最初からPlaywright、Git、データベース、AWSを使うと、接続、認証、権限の問題が同時に発生します。この演習では、サーバを1つ、読み取り専用ツールを1つだけ使います。

7.5.4何が起きているか

1　kitchen_board_mcp.py がAgentとは別のプロセスで動く

2　Agentは起動時に「使える道具の名前・説明・引数」を受け取る

3　Agentが get_kitchen_board を選ぶ

4　MCPサーバが現在のデータを返す

5　返った結果を読んで、Agentが次の判断をする

処理は7.1の4手順と同じです。MCPでは、ツールが別のプロセスで動きます。
