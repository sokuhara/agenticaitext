2.0What you do in this part

In this part you see what happens when you let an AI write the code. The speed and the limits, both at once.

By the end

You will be able to take a page showing a street in Osaka and turn it into your own theme. Change colours, replace signs, draw new things. You will not write code yourself.

The loop you repeat

1　Say what you want

2　Take the code the AI produces

3　Paste it, save, look

4　Say what to change

That is all you do. Between step 2 and step 3, the one moving the code around is you. That is the difference with Part 3. Keep it in mind.

2.1What Vibe Coding is

Vibe Coding is a term proposed by the AI researcher Andrej Karpathy in February 2025.

You do not follow the implementation details. You state what you want (the What). How to build it is left to the agent.

1　Describe what you want in words

2　The AI writes the code

3　Run it and look

4　Say what to fix

5　Repeat until it is right

An honest caveat "Needs less knowledge" is not "needs no knowledge". You still have to look at the result and decide whether it is what you asked for.

Nobody else will tell you that the sign is the wrong colour, or that the tower disappeared. That check is yours, and it is what this course is about.

Two things you touch in this exercise, one line each.

2.3.4The whole loop

Every change goes through these nine steps. Do not try to change everything at once.

1　Open shinsekai_remix.html in a browser

2　Open controls.txt in VS Code

3　Attach @controls.txt in the Continue chat

4　Ask for one change

5　Copy only the CSS the AI returns

6　Paste it into region A of shinsekai_remix.html

7　Only if there is a new shape, paste the SVG into region B

8　Save and reload the browser

9　If you like it, record the prompt and the result

You do not edit controls.txt controls.txt is a reference file that shows the AI which names exist. Leave it as it is.

What you paste into is shinsekai_remix.html. If you overwrite the reference file, you can no longer show the name list on the next request.

2.3.5Make the first change together

Before using the AI, do one change by hand. That fixes where you paste and how you reload, before anything else can go wrong.

If #name { property: value; } means nothing to you, read 2.3.10 first. Three minutes.

1. Find region A

Open shinsekai_remix.html in VS Code and search with Ctrl + F.

CONTROL PANEL: START

A little below it you will see these lines. That is region A.

#sky            { }
#left-shops     { }
#right-shops    { }
#street         { }
#far-buildings  { }
#tower          { }

2. Change one line

#sky            { filter: sepia(.7) saturate(2.4); }

3. Save and look

Ctrl + S to save, then Ctrl + R in the browser. If the sky changes colour, the mechanism works.

If nothing changed: did you save? did you reload? did you write it inside <style>? is #sky spelled correctly?

2.3.6Give controls.txt to Continue

If you did not install Continue You can do the same from a terminal. The steps are in Appendix A, A.10. This part assumes Continue.

How to hand it over

Continue has no file upload. It does not need one. It can read the files you have open in VS Code.

  1. In VS Code, File → Open Folder
  2. Open the folder containing controls.txt and shinsekai_remix.html
  3. Type @ in the Continue chat box
  4. Choose Files, then controls.txt
  5. Write your instruction and send

There is a second way. Open controls.txt, select all with Ctrl + A, then Ctrl + L. The selection goes into the chat.

Check that it actually attached Typing @ does not attach anything on its own. Pick the file from the list and confirm it. A badge with the filename appears above the chat box when it worked.

Without it, the model answers without ever seeing controls.txt. You still get a confident reply, but every name in it will be invented.
Never attach the 700 KB file shinsekai_remix.html also appears in the @ file list. Do not pick it. All 700 KB goes into the context, which is far more than a 4B model can hold.

If you really need to show part of the HTML, select just that region and press Ctrl + L.
Do not press Apply Continue puts an Apply button on code blocks. It can work, but with a 4B model it often rewrites more than it should. If the START / END markers disappear, you lose your paste target for the next round.

For this exercise, use the copy button at the top right of the block and paste into region A or B yourself. Deciding what goes where is the point.
Keep the mode on Chat Do not switch the dropdown to Agent. It will try to edit files on its own. With a 4B model that mostly fails. Handing file operations to an AI starts in Part 3.

Asking a 4B model: leave one blank

This is the most important part of this chapter. The local 4B model is small, and a normally-worded request often comes back unusable.

Ask it to "remove the text and make the sign saffron" and you get something like this.

#sign-kushikatsu {
  --board-color: SAFFRON;
}

That does nothing. SAFFRON is not a CSS colour. Declaring a variable on its own has no effect. The instruction to remove the text was ignored. It has the shape of an answer with nothing inside it.

Better prompting does not fix this Adding "do not use colour names" or "do not use variables" does not help. A 4B model will acknowledge the rule and break it in the same reply. It will even write "this violates your rule" and leave the code in.

Shortening the request does not help either. The problem is not output length. It is the number of decisions.

Leave exactly one thing to decide

This form works. Leave one blank and ask it to fill that in.

PROMPTFill in the blank. Output one line only. #sign-kushikatsu .ink { display: ______; } Replace ______ with the CSS value that hides the element.

You get one line back.

#sign-kushikatsu .ink { display: none; }

Colour works the same way. One blank per prompt.

PROMPTFill in the blank. Output one line only. #sign-kushikatsu .board { fill: ______; } Replace ______ with a hex color for saffron orange.
#sign-kushikatsu .board { fill: #ff9933; }
Why this works The model decides one word, none, or one value, #ff9933. You wrote the structure. The name, the property and the brackets cannot come out wrong.

A small model can make a choice. It cannot do the design. Keep the design and hand over only the choice. That is the principle when working with small models.

What region A looks like afterwards

Add the two lines just after #tower { } in region A. The region then reads like this.

.cover { display: none; }

#sky            { }
#left-shops     { }
#right-shops    { }
#street         { }
#far-buildings  { }
#tower          { }

/* CSS returned by the AI goes here */

#sign-kushikatsu .ink {
  display: none;
}

#sign-kushikatsu .board polygon {
  fill: #FF9933;
}
Paste in the right place The lines go immediately after #tower { }, inside region A. Not at the end of the file.

Leave the existing lines and the START / END markers alone. Delete them and you lose your paste target for the next round.

Save, reload, and the sign at the top left changes.

Before

After

Two lines of CSS changed the colour of the sign. Not one shape was edited.

Why .board polygon .board is a group. The thing that actually carries the colour is the <polygon> inside it. A fill on the group loses to a child that sets its own colour.

When a rule has no effect, try #name .board polygon instead of #name .board.

Without the blank

If you want the model to write the structure too, give it the name and the property.

PROMPTOutput one line of CSS only, no explanation. Hide the Japanese text layer of the kushikatsu sign. The text layer is #sign-kushikatsu .ink. Use display.

This sometimes works. The blank version is more reliable. Start with blanks and try this once you are comfortable.

This is the exercise Do not delete the exchanges that failed. What you asked, what came back, how you rewrote it. That is what you hand in.

The browser reads it top to bottom and draws what it finds. Nothing to compile, nothing to install. Save it and double-click.

Opening tag, content, closing tag. When the screen suddenly goes white, a closing tag has usually gone missing.

Names: id and class

You cannot ask an AI to change "that orange thing over there". Things need names.

<g id="lantern">
  ... many shapes ...
</g>

<g> is a group. It gathers many shapes under one name so they can be changed together.

id is a name used once. class is a label you can put on many things. The street file is built entirely out of these.

CSS: a rule that reaches a name

# means "the thing called this". . means "everything labelled this".

Edit the rules and the picture changes instantly.

filter: change thousands of shapes with one line

The street is about 6,000 shapes. You never edit them one by one. You shift the colour of a whole named group at once.

Press them and compare.

filter: none

hue-rotate turns colours around the colour wheel without changing their brightness. A negative angle pushes red towards orange. It is a quick way to move a Japanese shop sign towards an Indian palette.

2.3.12Talking to a 4B model

Small models follow narrow instructions well and wide ones badly.

The shape of a good instruction

PROMPT TEMPLATEHere is my CSS. Remove the Japanese writing from #sign-kushikatsu and make its board saffron orange. Change nothing else. Output only the CSS lines to add. Do not return the whole file. Do not write placeholders. Write real values. [paste controls.txt here]

That template does five things. Gives context. Names one change. Forbids collateral damage. Limits the output. Bans placeholders. Each one is doing work. Remove any of them and the result degrades.

The last two lines matter most Asked for long output, a 4B model gives up partway and writes {{ ... }} or ... rest of code .... Forbid that and the reply comes back short and correct.

2.4What we know so far

You changed a street without writing code. The speed is real.

You may also have seen the limits. A colour name that does not exist. A variable that is declared and never used. A rule acknowledged and then broken in the same reply. If none of that happened to you, look at your prompt log again and note what did.

Notice who did the work Between the model's answer and the picture changing, you copied, you chose where to paste, you saved, you reloaded.

The model never touched a file. That is exactly what Part 1 said: it takes text and returns text.

In Part 3 that changes. The agent reads files, writes them and runs commands by itself. You move from doing the work to approving it.
