01Install VS Code

You will open and edit files in these exercises. Any text editor would do, but Part 3 uses Cline, which is a VS Code extension. Installing it now saves time later.

Download from https://code.visualstudio.com/ and run the installer. All default settings are fine.

Open a working folder

First use File → Open Folder to open a folder to work in. If you skip this, the terminal will open somewhere you did not expect.

Open a terminal

Three ways. All open the same thing.

WayWhat to do
MenuTerminal → New Terminal
ShortcutWindows / Linux: Ctrl + Shift + `
macOS: Control + Shift + `
Command paletteCtrl (macOS Cmd) + Shift + P, then type "terminal"

That character is a backtick. It sits to the left of the 1 key, or where Shift + @ is on some layouts. It is not a single quote.

Terminal → New Terminal
No Terminal menu? When the window is narrow, the menu collapses into …. The screenshot above was taken in that state. Look for … to the right of File / Edit / Selection / View / Go / Run. Terminal is inside it.

Widening the window brings the menu back.

Check which shell you got

On Windows, make sure the terminal is PowerShell. The install command in the next section will not run in anything else.

How to tell
Top right of the terminalIt says powershell
Start of the promptIt begins with PS C:\...>

If you got cmd or Git Bash, click the v next to the + at the top right of the terminal and pick PowerShell.

Check where you are

pwd

If it prints the folder you opened, you are ready. If not, go back to File → Open Folder. Getting this wrong is a common reason files cannot be found later.

02Install Ollama

If you do not have it yet, get it from the official site. Open https://ollama.com/download and pick your OS.

https://ollama.com/download/windows

Windows

Two ways. Either one is fine.

A. Command. Copy the command shown on that page and paste it into PowerShell.

irm https://ollama.com/install.ps1 | iex

Opening a terminal is covered in section 01. Confirm it is PowerShell before you paste.

"Downloading Ollama for Windows..." means it worked

B. Installer. Press "Download for Windows" on the same page and run OllamaSetup.exe. If you are not comfortable with the command line, use this.

If it does not work CommandNotFoundException. You are not in PowerShell. Go back to "Check which shell you got" in section 01.

You mistyped the command. Use the copy button on the page instead of typing it. irm and iex are easy to get wrong.

Windows older than 10. Not supported. The requirements are on the download page.

macOS and Linux

On macOS, download the app from the same page and open it. On Linux, one line:

curl -fsSL https://ollama.com/install.sh | sh

Confirm it installed

ollama --version

A version number means it worked. If nothing appears, close the terminal and open a new one. Right after installing, the PATH may not be picked up yet.

03Check the model

ollama list

If qwen3.5:4b is in the list, you are ready. If not, fetch it.

ollama pull qwen3.5:4b
The 27B model is not installed locally The larger model used from Part 3 onwards lives on a shared server. It is not installed on your machine. It is around 18 GB, which is too much for a classroom to download at once.

Seeing only qwen3.5:4b in ollama list is correct. Connecting to the server is covered in Appendix A, section A.3.4.

04Say hello to it

ollama run qwen3.5:4b

Type a short question and press Enter. Type /bye to leave.

It looks frozen before it answers This model thinks before it answers. It first prints its reasoning inside a <think> tag, and only then the real answer. On a laptop this can take over 30 seconds.

It is not frozen. Wait.

05Shut Ollama down

Knowing how to stop it matters as much as installing it. A loaded model holds on to memory. If you leave it running, everything else on your machine gets slower.

Leave the chat

/bye

Ctrl + D does the same. Note that this only returns your terminal. The model is still in memory.

Unload the model

ollama ps
ollama stop qwen3.5:4b

Run ollama ps again. If the list is empty, it worked.

It also unloads on its own Ollama unloads a model roughly five minutes after you last used it. If you are not in a hurry, just wait.

If you need the memory now, or if ollama ps shows 100% CPU and things feel slow, an explicit ollama stop and reload sometimes helps.

Stop Ollama itself

Unloading the model does not stop the server. When the class ends, stop that too.

OSHow
WindowsSystem tray, bottom right (inside the ^ for hidden icons). Right-click the Ollama icon → Quit Ollama
macOSMenu bar, top right. Click the Ollama icon → Quit Ollama
Linuxsudo systemctl stop ollama if installed as a service.
If you ran ollama serve by hand, press Ctrl + C there
If nothing works afterwards Once Ollama is stopped, ollama run stops working and so do API calls from Cline. This is behind a lot of "but it worked yesterday" reports.

On Windows and macOS, launching the app again brings the server back. On Linux, sudo systemctl start ollama.

When unsure, run ollama ps. An error means the server is down. An empty list means the server is up and simply has no model loaded.

Summary

GoalCommand
Leave the chat/bye
See what is loadedollama ps
Unload a modelollama stop <model>
Stop the serverQuit from the tray or menu bar
Delete a downloaded modelollama rm <model>

ollama rm deletes the model files themselves. For a 27B model that frees around 18 GB. Delete models you no longer use. You can always ollama pull them again.

06Optional: chat inside the editor

You can now use the model from a terminal. This section is optional. If you want a chat panel next to your code, the way GitHub Copilot does, add one more extension.

You can skip this and still follow the course Part 3 onwards uses Cline. The extension in this section, Continue, is a different thing with a different job.

Both appear in the sidebar. You end up with two icons, and you can use both.
Continue (this section)Cline (required in Part 3)
What it doesAnswers questions, rewrites a selection, tab completionReads and writes files itself, runs commands
What you doRead the diff, decide whether to apply itApprove each action
Closest toGitHub CopilotAn agent that works on its own

Install it

Open the extensions panel with Ctrl + Shift + X (macOS Cmd + Shift + X). Search for Continue and press Install.

The top one, "Continue - open-source AI code agent", is the right one
Check the publisher Several extensions have Continue in the name. Pick the one published by Continue, with the blue check mark.

In the screenshot that is the top result. Vibrancy Continued, Markdown Continue and Cursor Auto Continue are unrelated extensions.

Connect a model

The first time you open the panel, you get a model setup screen. There are two tabs.

Press Local, on the right
Local, not API Key The API Key tab on the left is for cloud services such as OpenAI and Anthropic. Those need a key and cost money. This course does not use them.

Press Local, the tab with the llama icon.

The blue banner at the top, "Extension configuration is local only as of v2.0.0", just says settings are stored locally. Close it with ×.

Pressing Local makes Continue look for Ollama. Ollama is running at http://localhost:11434 with a green check means it found it.

It often defaults to Agent. Change it to Chat.

Why not Agent File edits and commands are Cline's job from Part 3 onwards. Overlapping roles get confusing.

Also, tool calling is unreliable on a model this small. Part 2 shows what that looks like in practice. Agent mode with a 4B model mostly produces failed attempts.

Try it

Type "hello" in the chat box. A reply means you are done.

Select some code and press Ctrl + L (macOS Cmd + L). The selection goes into the chat. You can ask "what does this function do?" or "write a test for this" without leaving the editor.

Replies feel slow qwen3.5:4b prints its <think> block before answering, as you saw in section 04. That is bearable in a chat panel. It is not usable for tab completion.

If you also want tab completion

Inline grey suggestions need a different model. It has to support fill-in-the-middle: looking at the code before and after the cursor. Chat models are not built for that.

Completion has to come back in roughly 0.2 seconds, or you stop waiting for it. For this one job, speed matters more than quality. Install a small model for it. Continue itself suggests the -base variant.

ollama pull qwen2.5-coder:1.5b-base
models:
  - name: Chat
    provider: ollama
    model: qwen3.5:4b
    roles: [chat]
  - name: Autocomplete
    provider: ollama
    model: qwen2.5-coder:1.5b-base
    roles: [autocomplete]

roles keeps the two apart. With spare VRAM you could use a 7B for completion, but if it gets slow you will stop using it. Start at 1.5B.

No suggestions appearing Disable other completion features, such as GitHub Copilot. Running two at once makes them fight. This is behind most "completion is not working" reports.

How to disable them, and what to check if that was not it, is in Appendix A, section A.9.
Two stages is easier 1. Install Continue and use only the sidebar chat. No extra model needed.
2. If the speed bothers you, add the completion model.

Setting up two models from the start gives you more places to get stuck.

07Create a GitHub account

Do this on day one You need it in Part 5. Creating it on the day means missing that exercise. Email confirmation and two-factor setup can take over 30 minutes.

If you already have an account, skip this section. Just check that you can log in.

Steps

  1. Open https://github.com/signup
  2. Enter an email address. Use one you can read throughout the course
  3. Choose a password and a username
  4. Enter the code sent to your email
  5. Set up two-factor authentication (app or SMS)
  6. Check that you can log in
Do not postpone two-factor setup GitHub requires it. If you put it off, you will be locked out when the deadline arrives.

An authenticator app on your phone (Google Authenticator, Microsoft Authenticator) is the safest option. Save the recovery codes somewhere else. Without them, losing your phone means a slow account recovery process.
