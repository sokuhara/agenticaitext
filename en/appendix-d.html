D.3How subtitles are made

Subtitles are produced by burn_subtitles() in video_tools.py. All the editing agent passes to add_subtitles is JSON of this shape:

[{"start": 0,   "end": 5,  "text": "Mumbai: 7 million riders a day"},
 {"start": 5,   "end": 10, "text": "Marine Drive, the Queen's Necklace"}]

The agent decides the timing and the words; the tool draws them, in two steps.

1　For each subtitle line, PIL draws a transparent 1280×720 PNG: a semi-transparent black band with white text, centred near the bottom (_subtitle_png)

2　ffmpeg's overlay filter lays that PNG over the video, with enable='between(t,start,end)' so it shows only in that interval (burn_subtitles)

def _subtitle_png(text: str, path: Path):
    """Draw one subtitle as a transparent PNG (PIL's bundled font, so it works everywhere)."""
    img = Image.new("RGBA", (W, H), (0, 0, 0, 0))
    d = ImageDraw.Draw(img)
    font = ImageFont.load_default(size=40)
    box = d.textbbox((0, 0), text, font=font)
    tw, th = box[2] - box[0], box[3] - box[1]
    x, y = (W - tw) // 2, H - 110
    d.rectangle([x - 24, y - 14, x + tw + 24, y + th + 18], fill=(0, 0, 0, 150))
    d.text((x, y), text, font=font, fill=(255, 255, 255, 255))
    img.save(path)


def burn_subtitles(src, dst, subtitles):
    """subtitles: list of {"start": s, "end": s, "text": "..."} -> overlaid on the video."""
    inputs = ["-i", str(src)]
    fc, prev = "", "[0:v]"
    for i, sub in enumerate(subtitles):
        png = BUILD / f"sub{i}.png"
        _subtitle_png(sub["text"], png)
        inputs += ["-i", str(png)]
        out = "[v]" if i == len(subtitles) - 1 else f"[s{i}]"
        fc += f"{prev}[{i + 1}:v]overlay=0:0:enable='between(t,{sub['start']},{sub['end']})'{out};"
        prev = out
    _run([*inputs, "-filter_complex", fc.rstrip(";"), "-map", "[v]",
          "-c:v", "libx264", "-preset", "veryfast", "-pix_fmt", "yuv420p", str(dst)])

One subtitle line is one PNG. ffmpeg also has a text filter, drawtext, and it is deliberately not used: it needs a font path that differs by operating system, and colons, apostrophes and quotes must be escaped in ways that reliably trip students up. Falling back to PIL's bundled font means the result is identical on Windows, Mac and Linux.

Limits of this approach
  • PIL's bundled font draws Latin script only. Hindi or Marathi on screen needs the font swap in D.6
  • Size is fixed at 40 px, one line. Long text runs off the right edge. The agent is told "one short line", but nothing enforces it (adding a length check is a good 7.3 modification)
  • Burned in, so it cannot be removed afterwards. A separate SRT file is shown in D.6

D.4Normalizing, joining, narration

Normalizing: normalize_clip

Clips from different services differ in size, frame rate and codec; joined as they are, they fail or stutter. So everything is first brought to 1280×720, 25 fps, H.264, silent. Portrait clips are shrunk and padded with black bars (scale … force_original_aspect_ratio=decrease, pad). seconds and start choose which part of the clip to use.

Joining: concat_with_crossfade

Normalized clips are joined in order with the xfade filter. Each join overlaps by fade seconds (default 0.6), so the finished length is the sum of the cuts minus 0.6 × (number of cuts − 1). When the length check in 7.4.6 says the video is short of 30 seconds, this overlap is usually what was forgotten.

Narration: narrate and mux_audio

narrate turns English text into an mp3 with edge-tts (a free library that uses Microsoft's speech service). The default voice is en-IN-NeerjaNeural, Indian English. It needs an internet connection and is unrelated to the shared lab server. mux_audio takes the video length as the reference: short audio is padded with silence, long audio is cut. That is why 7.4.6 fails a narration longer than the video: cut audio ends mid-word.

D.5Testing a tool on its own

The tools run without the editing agent (27B), and without any clips: ffmpeg can generate a test picture.

# try_subtitles.py  (put it in the agewec-mumbai folder and run: python try_subtitles.py)
import sys
sys.path.insert(0, "agent")
import video_tools as vt

vt.BUILD.mkdir(exist_ok=True)
# a 6-second test picture, so you need no clip at all
vt._run(["-f", "lavfi", "-i", "testsrc=size=1280x720:rate=25", "-t", "6",
         "-pix_fmt", "yuv420p", str(vt.BUILD / "joined.mp4")])

subs = [{"start": 0,   "end": 2.5, "text": "Mumbai: 7 million riders a day"},
        {"start": 2.5, "end": 5,   "text": "Marine Drive, the Queen's Necklace"}]
vt.burn_subtitles(vt.BUILD / "joined.mp4", vt.BUILD / "subtitled.mp4", subs)

vt.frame_at(vt.BUILD / "subtitled.mp4", 1.0, vt.BUILD / "f1.png")   # look at these two
vt.frame_at(vt.BUILD / "subtitled.mp4", 4.0, vt.BUILD / "f4.png")
print("done:", vt.probe_duration(vt.BUILD / "subtitled.mp4"), "seconds")

Open build/f1.png and build/f4.png: white text on a black band at the bottom of the frame, and in f4.png the apostrophe and comma come through as they are. After modifying the agent, run this unit test first to confirm the tools are intact, then do the full run. No wait for the 27B, so it takes seconds.

D.6Modifications

Most changes for "one new agent behaviour" in 7.3.2 live in agent_video.py or edit_tools.py. The following touch video_tools.py. Cline can do any of them; have the unit test from D.5 in place before you ask.

Change the font (non-Latin text)

# in _subtitle_png: use a real font file instead of PIL's bundled one
font = ImageFont.truetype("fonts/NotoSans-Regular.ttf", 40)   # put the .ttf in the project

Put a redistributable font file (Noto Sans, for example) in the project and replace load_default with truetype. For Devanagari, Noto Sans Devanagari. Add a line for the font's license to SOURCES.txt.

Change subtitle position or size

size=40 and y = H - 110 in _subtitle_png. For a portrait video W, H change too, and then the output size of normalize_clip must change with them.

Check subtitle length (a new success condition)

# in check(), one more success condition: no subtitle longer than 45 characters
for s in et.LAST_SUBTITLES:
    if len(s) > 45:
        problems.append(f"subtitle too long ({len(s)} chars): {s}")

This goes in check() in agent_video.py, not in video_tools.py. et.LAST_SUBTITLES holds the text the editing agent actually burned.

Write an SRT file as well

def write_srt(subtitles, path):
    """Write the same subtitle list as a .srt file (a sidecar, not burned in)."""
    def ts(t):
        h, r = divmod(t, 3600); m, s = divmod(r, 60)
        return f"{int(h):02}:{int(m):02}:{int(s):02},{int((s % 1) * 1000):03}"
    lines = []
    for i, sub in enumerate(subtitles, 1):
        lines += [str(i), f"{ts(sub['start'])} --> {ts(sub['end'])}", sub["text"], ""]
    Path(path).write_text("\n".join(lines), encoding="utf-8")

An output.srt next to the burned-in version lets you replace the subtitles when uploading to YouTube and the like. Call it inside add_subtitles, after burn_subtitles.

Add music

Mix a second audio input into the filter_complex of mux_audio with amix. Check the track's terms and add a music | … line to SOURCES.txt (7.2). Keep it around volume=0.2 so the narration stays audible.

Change a tool, revisit the checks Switch to portrait video, for instance, and the checks in 7.4.6 say nothing, but the tiles in contact_sheet (320×180) are still landscape. When you change what a tool assumes, ask Cline to list every function that depends on it before going on.
