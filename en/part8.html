8.0What you do in this part

What this part is about

The agent you built in Part 7 had state, tools, branching and approval. Here you move that design to work that is not coding.

Video production is the subject. The purpose is twofold: break multi-stage work into pieces, and separate what a machine can judge from what a person must judge.

By the end

You will be able to design a production workflow that runs from concept to a publish decision, and build a notebook that includes a correction loop.

The loop you repeat

1　Break the work into stages

2　Decide the state and the tools

3　Decide where a human approves

4　Run it

5　When it fails, send it back

The same shape as plan → implement → check → branch in Part 7. There are more stages, and nothing else changes.

8.0.1The final assignment

FINAL MISSIONPick one theme: something local that students should know, something genuinely useful about university life, or a social issue close to you. Build a production agent that completes a one-minute explainer video. The agent plans the structure, checks the facts, writes the script, specifies the material, assembles the video, reads the check result and corrects it. You approve the concept, verify the facts, and decide on publishing.
This is not a video contest You are not being marked on how the video looks. You are being marked on how you divided the work, where you put the human checks, and how you sent it back when it failed.

A polished video can still score low, if the flow runs straight through with no approval and no retry.

Text and still images are perfectly acceptable. With a fact-checking node and a threshold that hands over to a person, that is a good submission.

8.1Break video production into stages

First, split the work into stages. The same thing you did in Exercise 0.

Repetitive, multi-step, currently done by people. Break that apart.

StageWhat it does
ConceptNarrow the theme down to three points worth making
Fact checkConfirm each point is true. Keep the source
ScriptWrite text that fits one minute (roughly 150 words)
StoryboardSay what appears in each shot
MaterialPrepare images, audio and subtitles
AssemblyCombine into one video with ffmpeg
EvaluationCheck length, subtitle timing, volume, errors

The same shape as plan → implement → check in Part 7. Two things differ: the number of stages, and the fact that check cannot decide everything mechanically.

A test passes or fails. "Is this video any good" has no automated answer.

8.1.1So split the checking in two

A machine can judgeA person must judge
Whether the length is between 55 and 65 secondsWhether the concept matches the brief
Whether the subtitle character count matches the scriptWhether it is factually correct
Whether audio and subtitle timecodes line upWhether anything is misleading
Whether the output file playsWhether it should be published

The left column becomes your check node. The right column becomes an interrupt.

That split is the design work in this assignment.

8.3Hand concept through storyboard to the agent

These stages produce text: concept, fact check, script, storyboard, in that order.

Start by deciding, in one sentence, who should do what after watching this. Leave that vague and the agent simply adds plausible-looking footage.

Do not skip the fact-checking node Have an LLM write a script and plausible numbers and proper nouns appear in it. They read as naturally as the true parts, which is what makes them hard to catch.

This is section 1.2.3 from Part 1. Marking *guess in Exercise 0 was practice for exactly this.

Keep a source in sources for each point, and do not let a point without a source reach the script. Implement that as a node. "Be careful about it" is not an implementation.

On the standard route, you supply the three sources yourself. The workflow does not manufacture facts by searching the web.

On the extended route, you may gather candidates with search, MCP or an external API. The final verification is still done by a person.

Once the storyboard exists, put in the first human approval.

def review_plan(state: VideoState) -> VideoState:
    decision = interrupt({
        "points": state["points"],
        "sources": state["sources"],
        "script": state["script"],
        "question": "Is the concept sound and are the facts checked? (approve / revise)",
    })
    return {**state, "approved": decision == "approve"}

You stop here because what follows is hard to undo. Speech synthesis and video encoding cost time and money. Carry a wrong script forward and the amount you have to redo grows sharply.

This is the "before anything irreversible" rule from 7.4.

8.4After approval, assemble the video

Once approved, build the material and combine it.

ffmpeg -y \
  -f concat -safe 0 -i shots.txt \
  -i narration.wav \
  -vf "subtitles=subtitles.srt" \
  -c:v libx264 -pix_fmt yuv420p -c:a aac -shortest \
  output.mp4

You can let the agent write this, but read the command yourself.

Wrong ffmpeg options often produce a different result rather than an error. Do not rely on it stopping to tell you something is wrong.

Where it usually goes wrong Images at different resolutions between shots. Audio at inconsistent sample rates. Subtitles not encoded as UTF-8. A missing frame rate that changes the length.

ffmpeg happily runs in all of those cases. That is why 8.5 needs inspect_video.

8.5Evaluate, and run the correction loop

Inspect the finished video. The left column of 8.1.1, turned into code.

def check_video(state: VideoState) -> VideoState:
    info = ffprobe(state["video_path"])
    report = {
        "duration_ok": 55 <= info["duration"] <= 65,
        "has_audio": info["has_audio"],
        "subtitle_chars": count_chars(state["subtitle_path"]),
        "script_chars": len(state["script"]),
    }
    report["passed"] = (
        report["duration_ok"]
        and (info["has_audio"] or state["caption_only"])
    )
    return {**state, "check_report": report}

caption_only exists so that a run with no audio can still pass. You can finish with subtitles alone. A standard-route submission without TTS does not fail the check.

When it fails, decide which stage it returns to. Not back to the beginning.

Too long goes back to the script. No audio goes back to the material. Misaligned subtitles go back to assembly.

def route(state: VideoState) -> str:
    r = state["check_report"]
    if r["passed"]:
        return "review_final"
    if state["attempts"] >= 3:
        return "give_up"
    if not r["duration_ok"]:
        return "script"      # back to the script
    return "assemble"        # only redo the assembly

Submission requirement: run the correction loop at least once.

The first run always fails The starter notebook is configured so that the video comes out at about 70 seconds. That misses the 55-to-65 second window, so the first check fails. This is deliberate, so that everyone goes round the correction loop at least once.

Design where it goes from there. Back to the script to shorten the points, or back to the storyboard to trim seconds off a shot?

What this assignment is looking at is what happens when something fails.

8.6Reasons you might not publish

A finished video is not the same as one you should publish. Check these before the final approval.

ConcernWhat to check
Wrong informationDoes each of the three points have a source? Does the source actually say that?
CopyrightLicence terms for images, music and fonts. Any issue with what the generator was trained on
LikenessDoes a real person appear? Does anything resemble one?
DisclosureIs this a context where AI generation has to be stated?
CostWhat did one video cost? How many times did you rebuild it?
LogsCan you trace afterwards what ran at which stage?
