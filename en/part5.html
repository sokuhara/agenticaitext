5.1What you build in this part

MISSIONTurn the Vibe Chat from Parts 3 and 4 into a Flask application. Keep the messages in a Python list. Make it possible to verify, with a test, that an empty name and an empty message are rejected.

5.1.1Why move to Flask

Right now Vibe Chat lives entirely in the browser. The messages sit in a JavaScript array, so a reload clears them.

Move the data to the server and a browser reload no longer clears it. Restarting the server still will, because a Python list lives in memory too.

The real gain is different. Server-side code can be tested.

Being testable is the point In Part 4 you could not take the agent's report at face value, so in the end you checked by hand.

On the server side, "an empty name is rejected" can be checked in code. One command replaces a sequence of clicks. It also runs the same way every time, which a person does not.

5.2Decide what "done" means, first

Before you ask for anything, you decide what finished looks like.

Do not ask without deciding this If you do not decide, the agent will work to whatever it assumes you meant. Then it reports that the work is complete.

As Part 4 showed, that report only tells you it stopped. Whether it is done depends on conditions you wrote down first.

1The page opens in a browserA person looks

5.5Break it on purpose and watch the test fail

pytest says 2 passed. Now for an awkward question.

What does that passed prove?

That an empty name is rejected? No. It proves only that the test did not fail. A test that checks nothing also says passed.

Think of the smoke alarm on the ceiling. Silence does not mean the building is safe. An alarm with no battery is silent as well. There is exactly one way to know the alarm is real: hold smoke under it.

That is what you do here. Take the "reject an empty name" line out of app.py on purpose, so the app now accepts an empty name. You are the smoke. Then run pytest.

pytest saysMeaning
1 failedThe alarm went off. The test is watching that line. This is the result you want.
2 passedSmoke, and no sound. The test is watching nothing. What is broken is not the app. It is the test.

Normally failed is bad news. For these five minutes it is the other way round. failed means relief. Once you have seen it, put the line back and confirm it says 2 passed again. Done. (In the terminal, passed is printed in green and failed in red; that is what developers mean by "green" and "red".)

Why now From the next part on, every time app.py changes you run pytest once and conclude "nothing existing broke". You can only trust that conclusion to tests that really fail when something breaks. So you hold smoke under them once, here.

5.5.1Steps

1　Open app.py

2　Comment out the part that rejects an empty name (example below)

3　Save, then run pytest in the terminal

4　Confirm that one test fails and one passes (example below)

5　Uncomment it, save, and run pytest again

6　Confirm that both pass

2　What to comment out

Somewhere in the app.py Cline wrote, a few lines refuse an empty name. Search for name and empty. It looks roughly like this:

if not name:
    return render_template("index.html", error="User name cannot be empty.", messages=messages), 400

Put # at the start of each line from the if to the return. The whole block, not one line.

# if not name:
#     return render_template("index.html", error="User name cannot be empty.", messages=messages), 400

The app now accepts an empty name. Your file may look a little different from this example. What matters is that the "reject an empty name" part is gone.

4　What success looks like

The last lines of the pytest output should be like this:

FAILED tests/test_app.py::test_empty_name_is_rejected - assert ...
1 failed, 1 passed

Only the name test fails; the message test still passes. That is the evidence that the test is watching that line. Cline chose the test name, so anything with name in it is the same thing.

If it still says 2 passed, go to 5.5.2.

5.5.2If it did not fail

If it still says 2 passed, the thing to fix is the test. Have Cline fix it, written the same way as the three lines in Part 4.

PROMPTI commented out the empty-name check in app.py, but the tests still pass. Expected result: The test should fail when the empty-name check is removed. Inspect tests/test_app.py and show a short plan. Edit tests/test_app.py only. Do not edit the file yet.
The three lines from Part 4In this prompt
What you didCommented out the empty-name check in app.py
What happenedThe tests still passed
What should happen insteadWith that line gone, the test should fail

On top of that, the last lines say only tests/test_app.py may be edited. If Cline "fixed" app.py instead, it would just put the line back, and the test would stay decorative.

This is how you test a test You cannot check a test with another test. You break the code and see whether the test notices.

Doing this systematically, with tools that introduce the changes for you, is called mutation testing. Here you are doing one mutation by hand.
