Introduction

What to learn when AI writes the code

AI no longer just answers questions. It reads files, edits code and runs tests. In this course you will see that change with your own hands.

FIRST, WATCH THIS

You say "build me a submission tracker." Here is what happens in a few minutes.

Start with an empty folder. Give the Coding Agent this one instruction.

PROMPTBuild a web app in Python that tracks assignment submissions. Students, assignments, submission dates and status. I want to add records and see them in a list. Start it at the end and check that it runs.

Impressive. But would you submit this app as it is?

01From answering questions to doing the work

Look at the example again. The AI did not only write code. It created files, ran them, read the failure, fixed it and checked again.

Agentic AI is one way of using AI. You give it a goal. The AI plans the steps. It uses tools to carry them out. It looks at the result and decides what to do next.

A Coding Agent applies that idea to software development.

Here is the difference, using a bug fix as the example.

Ordinary generative AICoding Agent
You say"How do I fix this error?""One test is failing. Fix it."
You getA suggestion or a code sampleFixed code and a test result
The AI doesAnswers the questionFinds files, reads them, edits them, runs tests
You doApply the code and run itState the goal, make the important calls, check the result

The AI did not suddenly become capable of everything. What changed is that it can use tools. It reads files, runs commands, and feeds the result into its next move.

The important part The LLM is not driving your computer. It proposes what to do next. The program that actually touches files and runs commands is the agent host, such as Cline, and it acts within the permissions you gave it.

So the places where you can stop the work are outside the model: permissions, approvals and tests. You set them up in the environment.

The same idea applies outside coding. Paperwork, support requests, cleaning up data. Part 8 does exactly this with video production.

This course still uses coding as its subject, for two reasons.

  • Every change is visible as a diff, so you can see exactly what the agent did
  • Tests can check some of the behaviour for you, instead of you checking it by hand

Tests do not prove that the code is correct. They check that the behaviour you asked for is still there.

02Why now

AI can now carry out development work. This is not because the models write better prose. Three things had to come together first.

ConditionWhat it made possible
Tool calling became reliableThe AI can state which operation to run, with which arguments, in a structured form
Context windows grewIt can keep several files and a work history in view across many steps
It connected to the editorIt can use the editor, the terminal, the tests and version control

Together these changed what the AI can be used for. Not only a completion feature that suggests the next line, but an agent that carries out work within limits you set.

From Copilot to Pilot. Your work moves from implementation to design, verification and judgement.

Now go back to the app at the top of this page. Could you really submit it?

Input validation may be missing. The data may not survive a restart. Something no test covers may already be broken.

Building fast and building correctly are different things. So the question becomes: where does a human decide, and what limits do you put in place?

03What this course aims for

This course is not about handing development over to AI. It is about deciding how much to hand over, and staying responsible for the result.

You will still be the one who says what "done" means, and who approves each change.

By the end, you should be able to do the following.

  • Read what a Coding Agent looked at, what it changed, and on what grounds it called the work done
  • Let the AI implement something, then verify the result against tests, diffs and the specification
  • Narrow what you delegate, safely, using tests, linters, CI and permissions
  • Design a small agent in Python and LangGraph, with approval and retry built in
What you need Python 3.12. Basic programming and some terminal experience are enough. No prior knowledge of any particular framework is required.

Models run on your own machine or on a shared server provided for the class. The exercises are written so that you do not need a paid cloud API. Setup is in Appendix A.
