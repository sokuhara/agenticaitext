2.0この章で何をするか

この章では、AIにコードを書かせると何が起きるかを体験します。速さも、限界も、両方まとめて見ます。

この章を終えると

大阪・新世界の街を写した1枚のページを、自分のテーマに作り変えられるようになります。色を変え、看板を差し替え、新しいものを描き足す。コードは自分で書きません。

この章で繰り返す進め方

1　作りたいものを言う

2　AIが出したコードを受け取る

3　貼って、保存して、見る

4　直したい点を言う

人間がやるのは、この4つだけです。2から3のあいだ、コードを運んでいるのはあなたです。この点が、次のPART 3との分かれ目になります。いま覚えておいてください。

2.1Vibe Codingとは

Vibe Codingは、AI研究者のAndrej Karpathyが2025年2月に提案した言葉です。プログラムを1行ずつ書く代わりに、作りたいものを普通の言葉で説明し、コードはAIに書かせます。Karpathyはこれを「コードの存在をほとんど忘れてしまうような書き方」と表現しました。

人間は、実装の詳細を追いません。作りたいもの（What）だけを伝えます。作り方（How）はエージェントに任せます。

1作りたいものを言葉で伝える
2AIがコードを書く
3動かして見る
4直すところを言う
5できるまで繰り返す
従来のプログラミングVibe Coding
コードを書くのは自分で1行ずつAIが説明から生成する
自分の役割設計者・実装者・デバッガ案内役・検証者・レビュアー
必要な知識高い。構文を知っている必要がある低め。ただし「正しい状態」が分かる必要はある
主な入力正確なソースコード自然言語の指示とフィードバック
速度体系的だが遅い最初の動く版までは非常に速い
エラー対応コードを読んで手で直すエラー文をAIに貼って直させる
正直な注意 「必要な知識が低め」は「知識ゼロでよい」ではありません。出力をまったく読めないなら、正しい答えと自信満々の誤答を区別できません。モデルはどちらも同じ口調で返してきます。2.3.7で、今日必要な最低限を押さえます。

2.3.5Continueで controls.txt を渡す

Continueを入れていない場合 ターミナルから同じことができます。手順は付録AのA.10にあります。ただし本編はContinueで進めます。

渡し方

Continueにファイルのアップロード機能はありません。必要もありません。VS Codeで開いているファイルを、そのまま渡せます。

  1. VS Codeで File → Open Folder を選ぶ
  2. controls.txt と shinsekai_remix.html が入っているフォルダを開く
  3. Continueのチャット欄で @ を入力する
  4. Files を選び、controls.txt を指定する
  5. 指示を書いて送る
PROMPT@controls.txt Remove the Japanese writing from #sign-kushikatsu and make its board saffron. Output only the CSS lines to add. Do not return the whole file. Do not write placeholders. Write real values.

返ってくるのは、この2行です。

#sign-kushikatsu .ink   { display: none; }
#sign-kushikatsu .board { fill: #ff9933; }

これを controls.txt の #tower { } の下に足します。

全文を返させないこと controls.txt は70行あります。4Bに全文を返させると、途中で力尽きてプレースホルダに逃げます。

{{ modified board color to saffron }} や ... rest of code ... が返ってきたら、それです。中身がありません。変わる行だけを求めてください。

あわせて、あなたも ... existing code ... と打たないでください。それは差分編集の書式です。モデルが真似して、穴埋めテンプレートを返します。
添付できているか確認する @ と打っただけでは添付されません。候補から選んで確定してください。チャット欄の上にファイル名のバッジが出ていれば成功です。

出ていなければ、モデルは controls.txt を見ないまま答えています。それらしい返事は来ますが、名前は全部でたらめです。

もう1つの渡し方もあります。controls.txt を開いて Ctrl + A で全選択し、Ctrl + L。選択範囲がチャットに入ります。

700KBのファイルは渡さないこと @ のファイル一覧に shinsekai_remix.html も出てきます。選ばないでください。約700KBがそのままコンテキストに入り、4Bモデルは即座に破綻します。

HTMLの一部をどうしても見せたい場合は、その区間だけを選択して Ctrl + L を使ってください。
Apply ボタンを押さないこと Continueは返答のコードブロックに Apply を出します。変更対象を正確に選んでいれば使えますが、4Bモデルでは余計な部分まで書き換えることがあります。マーカーごと消えると、次の周で貼る場所が分からなくなります。

コードブロック右上のコピーボタンを使い、AとBの区間へ手で貼ってください。どこに何を貼るかを自分で決めることが、この演習の中身です。
モードは Chat のまま 左下のドロップダウンを Agent にしないでください。ファイルを勝手に書き換えようとします。4Bではまず失敗します。ファイル操作をAIに任せるのは、PART 3からです。

4Bへの頼み方：穴埋めにする

ここが、この章でいちばん重要な部分です。手元の4Bモデルは小さく、普通の頼み方では失敗します。

「文字を消して看板をサフランにして」と頼むと、こういうものが返ってきます。

#sign-kushikatsu {
  --board-color: SAFFRON;
}

動きません。SAFFRON という色名はCSSに存在しません。変数を宣言しただけでは何も起きません。文字を消す指示も無視されています。それらしい形はできていますが、中身がありません。

プロンプトを工夫しても直りません 「色名を使うな」「変数を使うな」と禁止を足しても、4Bは禁止を理解した上で違反します。返答の中で「これはあなたのルール違反ですが」と書きながら、そのまま出してくることさえあります。

量を減らしても同じです。問題は出力の長さではなく、判断の数です。

考えさせる場所を1か所に絞る

成功する形はこれです。穴を1つだけ空けて、埋めさせます。

PROMPTFill in the blank. Output one line only. #sign-kushikatsu .ink { display: ______; } Replace ______ with the CSS value that hides the element.

返ってくるのは1行です。

#sign-kushikatsu .ink { display: none; }

色を変える場合も同じ形にします。1回のプロンプトで、穴は1つ。

PROMPTFill in the blank. Output one line only. #sign-kushikatsu .board { fill: ______; } Replace ______ with a hex color for saffron orange.
#sign-kushikatsu .board { fill: #ff9933; }
なぜこれなら通るのか モデルが決めるのは none という1語、#ff9933 という1つの値だけです。構造はあなたが書いています。名前も、プロパティも、括弧の位置も、間違えようがありません。

4Bにできるのは、判断であって設計ではありません。設計を人間が持ち、判断だけを渡す。この分担が、小さいモデルを使うときの原則です。

A区間へ貼るとこうなる

返ってきた2つを、A区間の #tower { } の直後に足します。貼り付けた後のA区間は、こうなります。

.cover { display: none; }

#sky            { }
#left-shops     { }
#right-shops    { }
#street         { }
#far-buildings  { }
#tower          { }

/* AIから返ったCSSを、ここへ追加する */

#sign-kushikatsu .ink {
  display: none;
}

#sign-kushikatsu .board polygon {
  fill: #FF9933;
}
貼る場所を間違えないこと 追加するのは、A区間の #tower { } の直後です。HTML全体の末尾ではありません。

既存の行と、START／ENDのマーカーは削除しません。消すと、次の周で貼る場所が分からなくなります。

保存して、ブラウザを再読み込み。左上の串かつ看板が変わります。

変更前

変更後

CSSを2行足しただけで、左上の看板の地の色が変わりました。図形は1つも編集していません。

なぜ .board polygon なのか .board はグループです。実際に色を持っているのは、その中の <polygon> です。グループに fill を書いても、子が自分の色を持っていると勝ちます。

効かないときは、#name .board ではなく #name .board polygon を試してください。

穴埋めにしない書き方

構造まで書かせたい場合は、名前とプロパティを教えてしまいます。

PROMPTOutput one line of CSS only, no explanation. Hide the Japanese text layer of the kushikatsu sign. The text layer is #sign-kushikatsu .ink. Use display.

これでも通ることがあります。ただし穴埋めのほうが確実です。まず穴埋めで進め、慣れてきたらこちらを試してください。

この体験が課題の中身です うまくいかなかったやり取りを消さないでください。何を頼み、何が返り、どう書き直したか。それが提出物になります。

PART 3では、より大きなモデルに切り替えます。そのとき、頼み方をどれだけ変えられるかが分かります。いまの記録が、その比較の材料になります。

2.3.7うまくいかないとき

必ずうまくいかない場面が来ます。それは演習の失敗ではなく、演習そのものです。失敗はすべて記録してください。

症状起きていること対処
画面が真っ白タグか波括弧が閉じられていない直前の貼り付けを取り消し、もっと小さい変更で頼み直す
前の変更が消えたモデルがファイルを一から書き直した「既存のルールをすべて残し、#sky だけ変えて」と伝える
何も変わらない名前の綴り間違い、または存在しない名前controls.txt と1文字ずつ照合する
文字が空の四角になるそのフォントがマシンにないラテン文字を使う
コードでなく解説文が返る命令ではなく質問をした命令形で書き、「return only code」を付ける
終わらない、同じことを繰り返す一度に貼りすぎた700KBのファイルは絶対に貼らない。controls.txt だけ
色が変なところへ行ったhue-rotateが全部の色を動かした.board { fill: ... } で1色だけ指定する
こまめに保存する 気に入った状態になったら、ファイルを複製して work_01.html、work_02.html と名前を付けてください。バックアップがあれば復旧は10秒、なければ20分かかります。

2.3.10HTMLとCSSとは

この演習で触る2つを、1行ずつ説明します。

役割
HTML何があるかを書く。ものに名前を付ける
CSSそれをどう見せるかを書く。名前を指定して色や形を変える

この街のファイルもそうです。約6000個の図形がHTML側にあり、それぞれに名前が付いています。あなたが書き換えるのはCSS側です。

#sign-kushikatsu { fill: #e07b17; }
   ↑名前            ↑どう見せるか

これが読めれば演習は進みます。詳しい説明は2.3.7にあります。3分で読めるので、上のコードの意味が分からなければ先にそちらへ。

2.3.11実際に学んでいること

絵そのものは目的ではありません。重要なのは次の3点です。

  1. 構造は細部に勝つ。写真には6000個の図形があります。それを1行で全部変えられるのは、誰かが図形に名前を付けたからです。名前を付けることが、制御可能にするということです。これは人間にとってもAIにとっても同じです。
  2. 指示には形がある。同じ依頼でも、言い方が2通りあれば4Bモデルからは2通りの結果が返ります。10分以内に体感できます。
  3. 失敗が教材である。モデルはファイルを壊します。何が壊れ、どう復旧するかが、持ち帰れる技能です。
この演習の位置づけ この演習では、あなたがファイルを開き、AIの出力をコピーし、結果を確認します。次のPARTでは、この「読む・書く・実行する」の部分もAIに任せます。

2.3.12最低限必要な知識

今日は多くのコードを書きませんが、読める必要はあります。ここは15分ほどです。以下のデモはすべて動きます。触って確かめてください。

必修はこの5つだけです 1. id は部品の名前
2. CSSは、名前に対する変更指示
3. 1回に1変更
4. 現在のコードを渡す
5. 失敗したら小さく戻す

rect、circle、polygon、色相環の仕組みは触りたい人向けの寄り道です。読み飛ばして演習に進んでも、課題は完成します。

HTMLファイルはただのテキスト

ブラウザは上から下へ読んで、見つけたものを描きます。コンパイルもインストールもありません。保存してダブルクリックすれば動きます。

<p>Hello Mumbai</p>

開始タグ、中身、終了タグ。画面が突然真っ白になったときの原因は、たいてい終了タグの消失です。

SVG：数値でできた図形

スライダーを動かしてコードを見てください。

x 60
y 40
width 120 

<rect x="60" y="40" width="120" height="60"/>
yは下向きに増える 画像の一番上が y = 0 です。この街のファイルは一番下が y = 1066。何かを「上へ」動かしてほしいなら、yは小さくなります。全員が一度は間違えます。
要素描くもの必要な数値
rect長方形x y width height
circle円cx cy r
line直線x1 y1 x2 y2
polygon直線で囲んだ任意の形points="10,10 60,10 35,50"
text文字x y とタグの間の言葉

名前：id と class

「あそこのオレンジのやつ」を変えて、とAIに頼むことはできません。ものには名前が要ります。

<g id="lantern"> ...たくさんの図形... </g>

<g> はグループです。多数の図形をまとめて、名前を付けて一括で変更できるようにします。id は1つのものに1回だけ使う名前、class は複数のものに付けられるラベルです。街のファイルはすべてこれで構成されています。

CSS：名前に届くルール

# は「〜という名前のもの」、. は「〜というラベルの付いた全部」を意味します。

ルールを編集すると、右の絵が即座に変わります。

filter：1行で数千の図形を変える

街は約6000個の図形です。1つずつ編集することは決してありません。名前を付けたグループごと、色を一括でずらします。

押して比べてください。

filter: none

hue-rotate は、明るさを変えずに色を色相環上で回します。負の角度は赤をオレンジ寄りに押します。日本の店の看板からインドの看板へ向かう最短経路が、たまたまこれです。

2.3.13街のファイルの構造

写真は名前付きの部品に切り分けられています。図形そのものには触りません。部品を名前で変更します。

<g id="sign-kushikatsu">
  <g class="board">  ...看板の面...  </g>
  <g class="ink">    ...日本語の文字...  </g>
  <rect class="cover" ... />
</g>

すべての看板が3層構造なので、変え方も3通りあります。

#sign-kushikatsu .ink   { display: none; }   /* 文字を消す     */
#sign-kushikatsu .board { fill: #e07b17; }   /* 看板を塗り直す */
#sign-kushikatsu .cover { display: block; }  /* まるごと白紙化 */

自分の言葉や物は、ファイル末尾の add グループに追加します。

<text x="76" y="140" font-size="44" fill="#ffffff"
      font-family="Arial" font-weight="bold"
      text-anchor="middle">CHAI</text>

使える名前はすべて controls.txt の先頭に列挙されています。始める前にその一覧を読んでください。載っていない名前を発明することはできません。

文字化けについて デーヴァナーガリーなど、ラテン文字以外を看板に入れたい場合は、早い段階で試してください。マシンにインストールされているフォントに依存します。空の四角が並んで表示されたら、ラテン文字に切り替えてください。

2.3.144Bモデルへの話しかけ方

確実に動かすための3つの習慣です。

  1. 1回の指示につき1つの変更。「看板をサフラン色にして」は通ります。「看板をサフラン色にして、文字を消して、花飾りを足して、空も変えて」は壊れて返ってきます。
  2. 毎回かならず現在のコードを貼る。モデルは前のメッセージを覚えていません。今の状態を見せなければ、似たようなものを勝手に作り、それまでの作業を静かに消します。
  3. 正確な名前を使う。「#sign-blue を変えて」には解釈の余地がありません。「右にある青い看板を変えて」にはあります。

良い指示の形

PROMPT TEMPLATEHere is my CSS. Remove the Japanese writing from #sign-kushikatsu and make its board saffron orange. Change nothing else. Output only the CSS lines to add. Do not return the whole file. Do not write placeholders. Write real values. [paste controls.txt here]

このテンプレートがやっていることは5つです。文脈を与える／変更を1つだけ明示する／巻き添えを禁じる／出力の範囲を絞る／プレースホルダを禁じる。どれも仕事をしています。1つ抜けるだけで結果が崩れます。

最後の2行が効きます 4Bは、長い出力を求められると途中で諦めて {{ ... }} や ... rest of code ... を書きます。禁じておくと、短く正確に返ってきます。

2.4この章で分かったこと

今回は、AIが出したコードを人間が受け取り、貼り付け、動かしました。速さは体験できたはずです。数分で街の色が変わり、看板の文字が消えました。

同時に、限界も見えたはずです。AIはコードを書けても、自分ではあなたのファイルを読めず、テストも実行できません。ファイルを開いたのも、貼り付けたのも、結果を見て「違う」と判断したのも、すべてあなたです。

では、AIにファイルとターミナルという道具を渡したら、何が変わるでしょうか。
