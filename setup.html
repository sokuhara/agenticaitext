01VS Codeを用意する

この演習ではファイルを開いて書き換えます。テキストエディタなら何でも構いませんが、PART 3でCline（VS Codeの拡張機能）を使うので、いま入れておくと後が楽です。

https://code.visualstudio.com/ からダウンロードして、インストーラを実行します。設定はすべて既定のままで構いません。

作業フォルダを開く

最初に File → Open Folder で、作業用のフォルダを開いてください。これを先にやらないと、ターミナルを開いても意図しない場所にいます。

ターミナルを開く

3つの方法があります。どれでも同じものが開きます。

方法操作
メニューTerminal → New Terminal
ショートカットWindows / Linux：Ctrl + Shift + `
macOS：Control + Shift + `
コマンドパレットCtrl（macOSは Cmd）+ Shift + P → 「terminal」と打つ

` はバッククォートです。数字の1の左隣、または Shift + @ の位置にあります。シングルクォート（'）ではありません。

Terminal → New Terminal を選んだところ
メニューに Terminal が見当たらない場合 ウィンドウの幅が狭いと、メニューが … に畳まれます。上の画像も、その状態から開いています。File / Edit / Selection / View / Go / Run の右にある … を押してください。その中に Terminal があります。

ウィンドウを広げれば、メニューバーに直接出てきます。

シェルを確かめる

Windowsでは、開いたターミナルが PowerShell であることを確認してください。次の節のインストールコマンドは、PowerShell以外では動きません。

見分け方
ターミナルの右上powershell と表示されている
入力欄の先頭PS C:\...> で始まっている

cmd や Git Bash になっている場合は、ターミナル右上の + の隣にある v を押して、PowerShell を選び直します。

いる場所を確認する

pwd

開いたフォルダのパスが表示されれば準備完了です。違う場所にいたら、File → Open Folder からやり直してください。ここを間違えると、このあとファイルが見つからない原因になります。

02Ollamaを入れる

まだ入っていない場合は、公式サイトから入れます。https://ollama.com/download を開いて、自分のOSを選んでください。

https://ollama.com/download/windows を開いたところ

Windowsの場合

方法は2つあります。どちらか片方でかまいません。

A. コマンドで入れる。上のページに表示されているコマンドをコピーして、PowerShellに貼り付けます。

irm https://ollama.com/install.ps1 | iex

ターミナルの開き方は2.3.1のとおりです。PowerShellであることを確認してから貼り付けてください。

実行すると、ダウンロードが始まります。

Downloading Ollama for Windows... と出れば成功

B. インストーラで入れる。同じページの「Download for Windows」ボタンを押し、ダウンロードした OllamaSetup.exe を実行します。コマンドに慣れていない場合はこちらのほうが確実です。

うまくいかないとき CommandNotFoundException と出る。PowerShell以外のターミナルで実行しています。2.3.1の「シェルを確かめる」に戻ってください。

コマンドを打ち間違えた。手で入力せず、ページの右側にあるコピーボタンを使ってください。irm と iex は打ち間違えやすい部分です。

Windows 10より古い。対応していません。インストーラのページに要件が書かれています。

macOS / Linuxの場合

macOSは同じページからアプリをダウンロードして開くだけです。Linuxは次の1行で入ります。

curl -fsSL https://ollama.com/install.sh | sh

入ったことを確認する

ollama --version

バージョンが表示されれば成功です。表示されない場合は、ターミナルを一度閉じて開き直してください。インストール直後は、PATHが反映されていないことがあります。

03モデルが入っているか確認する

ターミナル（WindowsならコマンドプロンプトかPowerShell）を開いて実行します。

ollama --version
ollama list

一覧に qwen3.5:4b が出てくれば準備できています。出てこない場合は取得します。

ollama pull qwen3.5:4b
27Bは手元に入れません PART 3以降で使う qwen3.8:27b は、研究室の共有サーバにあります。各自のPCには入れません。18GBあり、全員が落とすと回線も容量も持ちません。

ollama list に qwen3.5:4b しか出なくても正常です。サーバへの接続方法は付録AのA.3.4にあります。

04一度話しかけてみる

ollama run qwen3.5:4b

短い質問を打ってEnter。抜けるときは /bye と入力します。

答える前に止まったように見えます このモデルは答える前に考えます。先に <think> タグの中に推論過程を出力してから、本当の答えが出ます。ノートPCでは、本文が出てくるまでに30秒以上かかることがあります。フリーズではありません。待ってください。

05Ollamaを切る

入れ方と同じくらい、切り方も先に知っておいてください。モデルはメモリを占有し続けます。27Bなら20GB近くです。切らないまま他の作業をすると、PCが重くなります。

対話から抜ける

ollama run のプロンプトが出ている状態から戻ります。

/bye

Ctrl + D でも同じです。ただし、これはターミナルの画面が戻るだけで、モデルはメモリに残っています。

モデルをメモリから降ろす

いま何が載っているかを見ます。

ollama ps

一覧に出たものを降ろします。

ollama stop qwen3.5:4b

もう一度 ollama ps を実行して、消えていれば成功です。

放っておいても降ります Ollamaは、最後に使ってから5分ほどで自動的にモデルを降ろします。急いでいなければ待つだけで構いません。

すぐにメモリを空けたいとき、または ollama ps に 100% CPU と出て動作が遅いときは、明示的に ollama stop してから入れ直すと直ることがあります。

Ollama自体を終了する

モデルを降ろしても、Ollamaのサーバは動き続けています。授業が終わったら、こちらも止めてください。

OS止め方
Windows 画面右下のタスクトレイ（隠れているインジケーターの ^ の中）にあるOllamaのアイコンを右クリック → Quit Ollama
macOS 画面右上のメニューバーにあるOllamaのアイコンをクリック → Quit Ollama
Linux sudo systemctl stop ollama（サービスとして入れた場合）
手で ollama serve を起動していたなら、その画面で Ctrl + C
切ったあとに動かなくなったら Ollamaを終了すると、ollama run も、ClineからのAPI呼び出しも通らなくなります。「昨日は動いたのに」の原因の多くはこれです。

Windowsとmacでは、アプリを起動し直せばサーバも復帰します。Linuxは sudo systemctl start ollama です。

迷ったら ollama ps を打ってください。エラーが返ればサーバが止まっています。空の一覧が返れば、サーバは動いていてモデルが載っていないだけです。

まとめ

やりたいことコマンド
対話をやめる/bye
いま載っているモデルを見るollama ps
モデルを降ろすollama stop <モデル名>
サーバごと止めるタスクトレイ / メニューバー から Quit
入れたモデルを消すollama rm <モデル名>

最後の ollama rm は、ダウンロードしたモデルのファイルごと削除します。27Bなら18GB空きます。使わなくなったモデルは消してください。消しても ollama pull で入れ直せます。

06発展：エディタの中でチャットする

ここまでで、ターミナルからモデルを使えるようになりました。この節は必修ではありません。ただ、GitHub Copilotのようにエディタの横にチャットを出したい場合は、拡張機能をもう1つ入れます。

やらなくても本編は進みます PART 3以降で使うのはClineです。この節で入れるContinueは別物で、役割が違います。
両方サイドバーに出ますが、アイコンが2つ並ぶだけで、同時に使えます。
Continue（この節）Cline（PART 3で必修）
やること質問に答える、選択範囲を書き換える、タブ補完自分でファイルを読み書きし、コマンドを実行する
人の作業差分を見て、適用するか決める実行のたびに承認する
近いものGitHub Copilot自律的に作業するエージェント

入れる

Ctrl + Shift + X（macOSは Cmd + Shift + X）で拡張機能のパネルを開きます。検索欄に Continue と入れて、Install を押します。

一番上の「Continue - open-source AI code agent」が正解
発行元を確認してください 検索すると、名前に Continue を含む別の拡張機能がいくつも並びます。選ぶのは、発行元が Continue（青いチェックマーク付き）のものです。

上の画像でいうと、一番上の「Continue - open-source AI code agent」です。Vibrancy Continued、Markdown Continue、Cursor Auto Continue などは、まったく別の拡張機能です。

入れると、画面左端のアイコンの列にContinueのアイコンが追加されます。ファイルのアイコンや虫眼鏡が縦に並んでいる、あの列です。

アイコンが見当たらない場合

順に確かめてください。

状態やること
左端のアイコン列そのものが見えない Ctrl + B（macOSは Cmd + B）でサイドバーを開く。
メニューからなら View → Appearance → Primary Side Bar
アイコン列はあるが、Continueが無い 列の下に … が出ていれば、そこに畳まれています。押して開くか、ウィンドウを縦に広げる
それでも無い Ctrl + Shift + P でコマンドパレットを開き、Continue と打つ。
Continue: Focus on Continue View が出れば入っています。選べば開きます
コマンドパレットにも出ない 入っていません。拡張機能のパネルに戻って、Installを押したか確認してください
画面下のパネルではありません Continueは、ターミナルと同じ下のパネルには出ません。左右のサイドバーに出ます。下に並んでいるのは Problems / Output / Terminal などです。「ターミナルしか見当たらない」場合は、見る場所が違います。

右側に置く

GitHub Copilotと同じ配置にしたい場合は、パネルを右へ移せます。3通りあります。

方法操作
ドラッグContinueのアイコンを右端へドラッグする。落とし先の枠が青く出たら離す
右クリックアイコンを右クリック → Move To → Secondary Side Bar
先に領域を出す右側の領域が無い場合は Ctrl + Alt + B（macOSは Cmd + Option + B）で開く

左に戻すときは、右クリック → Move To → Primary Side Bar です。

PART 3で入れるClineも、まったく同じ手順で右に置けます。左にファイル、中央にコード、右にAgent、という配置になります。

モデルをつなぐ

パネルを開くと、初回はモデルの設定画面が出ます。タブが2つあります。

初回の設定画面。押すのは右の「Local」
API Key ではなく Local です 左の API Key は、OpenAIやAnthropicのクラウドサービス用です。鍵の入力が必要で、課金もかかります。この教材では使いません。

押すのは、ラマのアイコンが付いた右の Local です。

上部の青いバナー「Extension configuration is local only as of v2.0.0」は、設定がローカル保存になったという案内です。× で閉じて構いません。

Localを押すと、Ollamaが検出されます。Ollama is running at http://localhost:11434 と緑のチェックが出れば、接続できています。

Add Chat model

続けて、使うモデルを登録します。次の画面が出ます。

このまま Connect を押せば設定ファイルが更新される
項目どうするか
ProviderOllama のまま
Install provider押さなくてよい。Ollamaが未インストールの人向けの案内です
ModelAutodetect のままでよい。入っているモデルを自動で拾います
Connect押す。config.yaml が自動で更新されます

手で設定を書く必要はありません。書く場合はこうなります。

models:
  - name: Chat
    provider: ollama
    model: qwen3.5:4b
    roles: [chat]

この状態になれば完了

入力欄の下が「Chat」と「qwen3.5:4b」になっていれば準備完了

入力欄の下に、2つのドロップダウンが並びます。

左のドロップダウンやること
Chat質問に答える。ファイルは触らない。これを選びます
Agentファイルを書き換え、コマンドを実行する
Plan変更計画を立てる

既定では Agent になっていることがあります。押して Chat に変えてください。

なぜAgentにしないのか ファイル操作とコマンド実行は、PART 3以降でClineが担当します。役割が重なると混乱します。

それに、4Bモデルはツール呼び出しが安定しません。PART 1で見たとおり、エージェントとして動かすには小さすぎます。Agentモードにすると失敗が増えるだけです。

右のドロップダウンが qwen3.5:4b になっていることも確認してください。

使ってみる

チャット欄に「こんにちは」と打ってください。返れば完了です。

コードを選択して Ctrl + L（macOSは Cmd + L）を押すと、選択範囲がチャットに入ります。「この関数は何をしている？」「テストを書いて」といったやり取りを、エディタを離れずにできます。

応答が遅く感じます qwen3.5:4b は答える前に <think> を出すモデルです。04で見たとおりです。チャットなら待てますが、タブ補完には使えません。

タブ補完も使いたい場合

灰色の候補が出るタブ補完は、チャットとは別のモデルが要ります。カーソルの前だけでなく、後ろのコードも見て間を埋める形式（fill-in-the-middle）に対応している必要があるためです。チャット用のモデルは、これを想定して作られていません。

補完は0.2秒で返らないと使いません。速さが正義です。小さいモデルを別に入れます。Continueの画面にも、この -base 付きのモデルが案内として出ます。

ollama pull qwen2.5-coder:1.5b-base
models:
  - name: Chat
    provider: ollama
    model: qwen3.5:4b
    roles: [chat]
  - name: Autocomplete
    provider: ollama
    model: qwen2.5-coder:1.5b-base
    roles: [autocomplete]

役割（roles）で使い分けます。VRAMに余裕があれば補完用を7Bに上げられますが、遅くなると使わなくなります。1.5Bから始めてください。

補完が出ないとき GitHub Copilotなど、他の補完機能を無効にしてください。同時に有効だと干渉します。補完が出ないという相談の原因は、たいていこれです。

切り方と、それでも出ない場合の確認手順は付録AのA.9にまとめてあります。
2段階で試すのが楽です 1. まずContinueを入れて、サイドバーのチャットだけ使う。モデルの追加は不要
2. 遅さが気になったら、補完用の qwen2.5-coder:1.5b を足す

最初から2モデル構成にすると、設定が増えて詰まりやすくなります。

07GitHubアカウントを作る

初日のうちに作ってください PART 5で使います。当日に作ろうとすると、その日の演習に入れません。メール確認と2要素認証で30分以上かかることがあります。

すでに持っている人は、この節を飛ばして構いません。ログインできることだけ確認してください。

手順

  1. https://github.com/signup を開く
  2. メールアドレスを入力する。授業中ずっと受信できるものにしてください
  3. パスワードとユーザー名を決める
  4. メールに届いた確認コードを入力する
  5. 2要素認証を設定する（アプリまたはSMS）
  6. ログインできることを確認する
2要素認証の設定を飛ばさないこと GitHubは2要素認証を必須にしています。後回しにすると、期限が来た時点でログインできなくなります。

スマートフォンの認証アプリ（Google Authenticator、Microsoft Authenticator など）を使うのが確実です。復旧コードは必ず保存してください。スマートフォンを失くすと入れなくなります。

作れたら報告してください

ユーザー名を講師に伝えてください。誰が完了したかを確認します。

どうしても作れない場合 会社のメールしか使えない、電話番号での認証が通らない、といった理由で作れないことがあります。

その場合でもPART 5は進められます。5.6の破壊テストのうち3つはローカルで完結します。残り1つ（プルリクエスト）だけができません。章の目的は達成できます。

作れなかった場合は、初日のうちに講師へ知らせてください。
