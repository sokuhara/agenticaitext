PART 4

このアプリ、本当に提出できる？

Agentが「完成しました」と言っても、それは完成の根拠になりません。自分で操作して確かめ、問題があれば直させます。この章ではコードを書かず、テストと承認の判断だけを行います。

前章まで
PART 3で、Clineが自分でファイルを読み書きし、コマンドを実行してアプリを組み上げました。速さは体験できたはずです。
この章
PART 3で作ったアプリを自分でテストし、見つかった問題をClineに直させます。修正のループを1周、最後まで通します。
次章へ
PART 5では、この確認を機械にやらせます。人間が毎回やると必ず忘れるからです。

4.0この章で何をするか

MISSIONPART 3で作った Vibe Chat をテストしなさい。 問題を1つ見つけ、Clineを使って修正し、同じテストをもう一度行いなさい。

3つの作業を順に行います

やること誰が目安
1テスト項目を1つ選ぶ（4.1）人間5分
2ブラウザで実際に操作する（4.1）人間15分
3問題を記録する（4.2）人間15分
4Planモードで修正を依頼する（4.3.1）Cline10分
5Planを判断する（4.3.2）人間10分
6差分を判断する（4.3.3）人間10分
7再テストする（4.3.4）人間15分

およそ1時間20分です。7つのうち6つが人間の作業です。Agentがやるのは、調べて直すところだけです。

使うもの

PART 3で作った index.html です。ブラウザで開ける状態にしておいてください。

3.4の発展課題（Deleteボタン）まで終えている場合は、そちらを使います。Deleteがある版のほうが、テストする項目が増えます。

仕様どおりの動作を欠陥と呼ばないこと 再読み込みで投稿が消えるのは、PART 3で「JavaScript配列だけに保持する」と指示したからです。仕様どおりです。

複数のタブで共有されないのも同じです。これらは不具合ではありません。この章で探すのは、指示していないのに起きてしまう問題です。

4.1テスト項目を1つ選ぶ

次から1つ選びます。全部やる必要はありません。1件で、修正のループを最後まで通すことが目的です。

操作
1User name を空欄にして Send
2Message を空欄にして Send
31000文字を入力して Send
4<h1>Hello</h1> を入力して Send
5メッセージを2件作り、1件目を Delete
6Send と Delete を何度か繰り返す

5と6は、PART 3の3.4（発展課題）でDeleteを実装した場合だけです。

自分の手で操作してください 入力欄に文字を入れ、ボタンを押し、画面を見る。これを人間がやります。

Clineに「テストして」と頼まないでください。「動きました」という報告は合格の根拠になりません。

4.1.11000文字の作り方

手で打つ必要はありません。適当な文章をコピーして、10回ほど貼り付けてください。枠からはみ出すかどうかが分かればよいので、正確に1000文字である必要はありません。

4.2問題を記録する

3つを書きます。3番目が重要です。

書くこと
1行った操作
2実際に起きたこと
3本来どうなるべきか

4.2.1書き方の例

メッセージ欄に1000文字を入力してSendを押した。
文字がカードの外へはみ出した。
カード内で折り返して表示されるべきである。
3番目は、あなたが決めます 「本来どうなるべきか」は、Agentには決められません。仕様を決めるのは人間の仕事です。

折り返すのか、途中で切るのか、そもそも1000文字を入力できないようにするのか。どれも正解になりえます。あなたが選んだものが仕様になります。

ここを書かずに「はみ出します、直して」とだけ伝えると、Agentは勝手に決めます。意図と違う直し方をされます。
問題が見つからない場合 27Bが作ったものは、意外としっかりしていることがあります。6項目すべて問題なしでも、失敗ではありません。

その場合は「改善したい点」を1つ選んでください。投稿時刻の表示、削除の確認、長い名前の省略など。「本来どうなるべきか」を書く練習は同じようにできます。

4.3Clineに修正させる

4.3.1Planモードで依頼する

Plan に切り替えてから送ります。4.2で書いた3つを、そのまま英語にします。

PROMPTThe message layout breaks when I submit a very long message. Expected result: The text should wrap inside the message card. Inspect index.html and show a short plan. Edit index.html only. Do not change the current design or other functions. Do not edit the file yet.

上から3行目までが実際に起きたこと、`Expected result` が本来どうなるべきかです。あなたの記録に合わせて書き換えてください。

最後の4行は必ず入れます Edit index.html only　変更範囲を限定する
Do not change the current design or other functions　巻き添えを防ぐ
Do not edit the file yet　Planを読む前に実装させない

1つ抜けるだけで、余計な変更が混ざります。

4.3.2Planを人間が判断する

Clineが計画を出します。読んでから次へ進みます。

確認すること問題があったら
問題と関係のある変更か関係ない箇所を触る計画なら、指摘して出し直させる
index.html 以外を変更しないか別ファイルを作る計画なら、1ファイルで済む方法を求める
SendやDeleteを壊さないか書き換える計画なら、理由を確かめる
不要な機能を追加していないかデザインの刷新、新機能は頼んでいません

問題がなければ Act へ切り替えます。問題があれば、その場で指摘して計画を出し直させます。

4.3.3差分を人間が判断する

Actにすると、Clineが変更を提示します。SaveかRejectかを、あなたが選びます。

差分の中身判断
必要な変更だけSave
全体を書き直しているReject
外部ライブラリを追加しているReject
別の機能を削除しているReject
差分を見ずに押さないこと 見ずにSaveを押していると、承認の意味がありません。何が変わるのかを読んでから決めてください。

Rejectしたら、理由を書いて出し直させます。そのやり取りが提出物になります。

4.3.4人間が再テストする

Saveしたら、ブラウザを再読み込みします。確認するのは3つです。

1　4.1で選んだ操作を、もう一度行う

2　Send が今までどおり動くか確認する

3　Delete が今までどおり動くか確認する（実装している場合）

2と3を飛ばさないでください。直したつもりで、別のところを壊していることがあります。

Agentの「修正しました」は根拠になりません 根拠になるのは、あなたが操作して結果が変わったことだけです。

直っていなければ、何が起きたかを伝えて再修正させます。4.3.1へ戻ってください。

4.4提出物

6つを1つのファイルにまとめてください。

提出物内容
修正前問題が分かる画像
問題の記録操作、実際の結果、期待する結果
PlanClineが提示した計画
人間の判断SaveまたはRejectを選んだ理由
修正後問題が直ったことが分かる画像
再テスト問題、Send、Deleteの確認結果
「人間の判断」がいちばん重要です なぜSaveしたのか。なぜRejectしたのか。1〜3行で構いません。

「差分がindex.htmlのCSS3行だけで、Send機能に手を入れていなかったのでSaveした」
「デザイン全体を書き換える計画だったのでRejectし、折り返しの指定だけを頼み直した」

この判断が、この章で身につけるものです。

4.4.1誰が何をしたか

提出前に、自分の作業を振り返ってください。

担当やったこと
あなた問題を見つける。本来どうなるべきかを決める。Planを確認する。差分を承認する。最終確認をする
Clineコードを調べる。修正案を出す。変更を適用する

仕様を決めるのも、承認するのも、確認するのも人間です。Agentがやったのは、調査と修正だけです。

提出先は、演習1と同じピア評価システムです。Assignment 2 のカードから提出します。

4.5この章で分かったこと

Agentが「完成しました」と言っても、それは完成の根拠になりません。

根拠になるのは、あなたが操作して結果を確かめたことだけです。この章では、それを手で行いました。

毎回これをやりますか 1件直すのに1時間20分かかりました。操作して、記録して、依頼して、Planを読んで、差分を見て、また操作する。

変更のたびに繰り返せますか。Sendが動くか、Deleteが動くか、毎回忘れずに確かめられますか。

やれません。人間は忘れます。だから機械にやらせます。

PART 5では、この確認を自動化します。「Sendが動く」「Deleteが動く」のように機械が判定できるものは、テストになります。

一方で、「本来どうなるべきか」を決めることと、差分を承認することは自動化できません。それは人間に残ります。

その切り分けが、次章の入り口です。
