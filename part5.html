5.2完了条件を先に決める

依頼する前に、何ができていれば「完成」なのかを、あなたが決めます。

これを決めずに頼まないこと 決めずに依頼すると、Agentが勝手に決めます。そして「完成しました」と報告します。

PART 4で確かめたとおり、その報告は根拠になりません。根拠は、あなたが決めた条件を満たしているかどうかです。

5.2.1最低限の5項目

条件確かめ方
1ブラウザで画面が開く人間が見る
2メッセージを送ると一覧に増える人間が操作する
3名前を空のまま送ると、メッセージは増えず、画面に「User name cannot be empty.」が出るテストが判定する
4メッセージを空のまま送ると、メッセージは増えず、画面に「Message cannot be empty.」が出るテストが判定する

5.4.1何を確かめているかを読む

tests/test_app.py を開いてください。2つのテストが、何をしているかを説明できますか。

だいたい、こういう形になっているはずです。

def test_empty_name_is_rejected(client):
    r = client.post("/send", data={"name": "", "message": "hello"})
    # 登録されていないことを確かめる
    ...
読めなければClineに聞いてください 「このテストは何を確かめていますか。1文で説明してください」と聞けば答えます。

読めないテストは、あなたのテストではありません。次の5.5で、本当に効いているかを確かめます。

5.5わざと壊して、落ちることを確認する

いま pytest は 2 passed と言っています。ここで1つ、意地の悪い質問をします。

その passed は、何を証明していますか。

「空の名前は登録されない」ことでしょうか。違います。証明しているのは「テストが落ちなかった」ことだけです。何も確かめていないテストも、passed になります。

天井の火災報知器を思い出してください。鳴っていないから安全、とは言えません。電池が抜けていても鳴りません。報知器が本物かどうかを知る方法は1つ。煙を当ててみることです。

ここでやるのは、それです。app.py から「空の名前を弾く行」をわざと外して、アプリが空の名前を受け付ける状態にします。つまりあなたが煙を出します。そして pytest を打ちます。

pytest の結果意味
1 failed報知器は鳴った。テストはその行を見張っている。これが正解です。
2 passed煙を当てても鳴らなかった。テストは何も見ていない。壊れているのはアプリではなく、テストのほうです。

ふだんは failed は悪い知らせですが、この5分間だけは逆です。failed を見て安心してください。見終わったら行を戻し、2 passed に戻ることを確かめて終わりです。（ターミナルでは passed が緑、failed が赤で出ます。開発者が「緑」「赤」と言うのはこれのことです。）

なぜ今これをやるのか 次の章から、app.py を変えるたびに pytest を1回打って「既存の動作は壊れていない」と判断します。その判断は、壊れたら本当に failed になるテストにしか任せられません。ここで1回、煙を当てて確かめておきます。

5.5.1手順

1　app.py を開く

2　空の名前を弾いている部分を、コメントアウトする（下の例）

3　保存して、ターミナルで pytest を実行する

4　1つ落ちて、1つ通ることを確認する（下の例）

5　コメントアウトを戻して保存し、もう一度 pytest

6　2つとも通ることを確認する

2　どこをコメントアウトするか

Clineが書いた app.py の中に、名前が空なら受け付けない、という数行があります。name と empty で検索すると見つかります。形はおおよそこうです。

if not name:
    return render_template("index.html", error="User name cannot be empty.", messages=messages), 400

この if から return までを、行頭に # を付けてコメントにします。1行ではなく、そのブロック全部です。

# if not name:
#     return render_template("index.html", error="User name cannot be empty.", messages=messages), 400

これでアプリは、名前が空でも登録してしまう状態になりました。あなたのファイルの書き方は、この例と少し違って構いません。「名前が空なら弾く」の部分を丸ごと消せていればよいです。

4　何が見えれば成功か

pytest の出力の最後が、こうなっていれば成功です。

FAILED tests/test_app.py::test_empty_name_is_rejected - assert ...
1 failed, 1 passed

落ちたのが名前のテストだけで、メッセージのテストは通っている。これが「テストがその行を見張っている」証拠です。テストの名前はClineが付けたものなので、name が入っていれば同じものです。

最後が 2 passed のままなら、5.5.2へ。

5.5.2落ちなかった場合

2 passed のままなら、直す相手はテストです。Clineに直させます。書き方はPART 4の3行と同じです。

PROMPTI commented out the empty-name check in app.py, but the tests still pass. Expected result: The test should fail when the empty-name check is removed. Inspect tests/test_app.py and show a short plan. Edit tests/test_app.py only. Do not edit the file yet.
PART 4で書いた3行このプロンプトでは
行った操作app.py の空の名前を弾く行をコメントアウトした
実際に起きたことそれでもテストが通った
本来どうなるべきかその行を外したら、テストは落ちるべき

それに加えて、触ってよいのは tests/test_app.py だけと最後に書いてあります。app.py を直されたら、壊した行が戻るだけで、テストは飾りのままだからです。

これがテストの検査です テストが正しいかどうかを、テストで確かめることはできません。壊して落ちるかを見るしかありません。

この作業をミューテーションテストと呼びます。実務でも使われる考え方です。

5.6実装を進める5つの手順

最初に、5.5でコメントアウトした行を元に戻し、pytestを実行してください。2 passedを確認してから先へ進みます。

この章では、次の5手順で機能を足します。先にこれを覚えてください。5.7で、この順に進めます。

1　完了条件を書く　何ができたら終わりか

2　変わる場所を予想する　どのファイルのどこが変わるか

3　Planで依頼する　計画を読んでから実装させる

4　差分を承認する　予想と合っているか確かめる

5　pytest とブラウザで確認する　両方やる

5.6.1手順を飛ばすと何が起きるか

飛ばした手順起きること
1 完了条件Agentが勝手に決める。「完成しました」の意味が分からない
2 予想差分を読んでも、それが妥当か判断できない
3 Plan実装が始まってから方針の誤りに気づく
4 承認関係ない場所まで書き換えられる
5 確認テストは通るが画面が壊れている、が起こる
2番がいちばん飛ばされます 予想を書かずに差分を見ると、読んでいるつもりで読めていません。「それらしいコードだからSave」になります。

先に「app.py のこの関数と、templates/index.html のこの部分が変わるはずだ」と書いておくと、差分が予想と違ったときに気づけます。

5.7予定外の変更要求

動くものが一度できたあとに、要件が変わります。実務ではこちらが普通です。

緊急連絡 投稿の内容に、他人を傷つける言葉が含まれていた、という報告がありました。

禁止語を含む投稿を登録できないようにしてください。禁止語の一覧は app.py の中にリストとして持ちます。

登録を拒否したときは、画面に理由を表示します。既存の機能は1つも壊さないでください。

5.7.1まず、自分で予想する

Agentに投げる前に書いてください。予想を書いてから差分を見るのと、いきなり差分を見るのとでは、レビューの質がまったく違います。

  • データはどう変わるか（禁止語のリストをどこに置くか）
  • 処理はどう変わるか（送信のどの時点で判定するか）
  • 画面はどう変わるか（拒否の理由をどこに出すか）
  • 既存のテストのうち、どれが落ちるか
最後の項目を考えてください 既存のテストは「空の名前は登録されない」「空のメッセージは登録されない」でした。禁止語の判定を足すと、これらは落ちますか。

落ちないはずです。落ちるとしたら、実装が既存の処理を壊しています。

5.7.2完了条件を書く

条件確かめ方
1禁止語を含む投稿は登録されないテスト
2禁止語を含まない投稿は、これまでどおり登録されるテスト
3拒否されたとき、理由が画面に出る人間が見る
4既存のテストが全部通ったままテスト

2番を忘れないでください。「禁止語を弾く」だけを頼むと、全部弾く実装でもテストが通ります。

Keep the plan under 10 lines. Do not edit the file yet. Show the plan only.

確認なぜ

禁止語の判定は、大文字小文字を区別するかどちらでもよいが、意図して決まっているか

5.9この章で分かったこと
